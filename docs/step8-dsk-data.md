# Type 2 DSK data access and closure

All seven operations use the existing raw DSK domain. Read operations take an opaque token obtained by opening the file and a value descriptor from DLA traversal of its segment. Descriptors can travel through the RPC codec and can be copied. A read validates the eight descriptor words against the open file at its integer component base and checks the type-2 layout, counts and bounds before calling CSPICE. Equal descriptors on separately opened claims for the same file remain usable. The handle registry rejects tokens from other clients and retired claims.

| Method                                      | Returned data and indexing                                                                                                                                                   |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dskd02(handle, dladsc, item, start, room)` | Flat double components using a **zero-based** start. Keywords 15–19 select the descriptor, vertex bounds, voxel origin, voxel size and xyz vertex components.                |
| `dski02(handle, dladsc, item, start, room)` | Flat signed integer components using a **zero-based** start. Keywords 1–14 cover counts, grid data, one-based plate vertex IDs and optional lookup lists.                    |
| `dskp02(handle, dladsc, start, room)`       | Rows of one-based plate vertex IDs. Start is a **one-based plate number** and room is counted in plates.                                                                     |
| `dskv02(handle, dladsc, start, room)`       | Rows of Cartesian xyz coordinates in km. Start is a **one-based vertex number** and room is counted in vertices.                                                             |
| `dskn02(handle, dladsc, plid)`              | The plate's oriented **unit** normal, determined by its right-handed vertex winding. The registered inclined face distinguishes all three components.                        |
| `dskz02(handle, dladsc)`                    | Named integer counts `{nv,np}` for vertices and plates.                                                                                                                      |
| `dskcls(handle, optmiz)`                    | Close this open reference. With true, a writer's DAS records are segregated for reading. With false, CSPICE flushes buffered writes and closes the file without segregation. |

## Partial pages and signed arithmetic

The four page routines return exactly the number of values or rows written by CSPICE. Final pages can be shorter than the caller's capacity. A request starting beyond the last valid row or array-valued item signals `INDEXOUTOFRANGE`. Ordinary nonpositive room signals `VALUEOUTOFRANGE`. The row readers check start before room and multiply room by three for their internal scalar request. Tests preserve the diagnostic precedence and observe valid reads after an error. The public result never exposes unused output slots.

A positive room is bounded by the length of the descriptor’s physical integer or double component before allocation. Even `2147483647` on a small valid segment can return its last row. The limit for one allocated buffer is a signed 32-bit native byte count or 256 MiB on WASM. Nonrepresentable internal offset additions and negative row counts whose multiplication would overflow are rejected before dispatch. The N0067 integer reader uses uninitialized size and address variables when a scalar keyword is requested with a nonzero offset and positive room. The public contract requires zero offset for these scalar items. These guard cases are separate from successful and failing scientific calls.

The N0067 row readers and normal calculation use private counts and indices after fallible internal lookups. The shared shim validates physical addresses, compares descriptor words, checks the data type, and reads the ten type-2 integer header words using initialized storage. Component sizes and products are checked with wider integers before calling the canonical routine. Normal evaluation additionally checks the selected plate’s three indices. The close path retains the token after an error and retires it only after success. Returned pages and their inner rows own their storage. Each adapter snapshots the input descriptor before dispatch.

## Fixtures and independent evidence

The existing MIT-licensed `audit-multi-dsk.bds` is an authored four-segment tetrahedron generated and read back with the locked SpiceyPy library. The existing Apophis fixture supplies a different mesh with unequal counts. Both are read-only. Optimized and unsegregated close tests create new, uniquely named scratch DSKs, reopen them and observe the complete mesh. An additional two-segment writer test reads each physical output in a separate SpiceyPy process, including bytes produced by the actual WASM filesystem. Comparing mesh contents works for both physical record arrangements. No physical-size or speed claim is made. [Fixture provenance](../packages/py-parity-checking/fixtures/README.md)

SpiceyPy 6.0.3 returns full capacity arrays from its four page wrappers, discarding the C output count. The independent binding uses the same locked library with exact ctypes argument types, initialized output and guard rows. It reads `n`, checks that padding survives and compares the entire returned prefix. A separate positive probe compares all four wrappers on the same authored tail. The normal, counts and close workflows invoke the ordinary locked wrappers.

The 47 registered workflows contain 235 steps, 95 calls to the added routines and 16 expected toolkit errors. All 94 registered Node/WASM comparisons, 11 public/oracle tests, 14 native tests and 31 WASM tests passed. The public checks cover token ownership, partial pages, both physical close modes and repeating a writer workflow on one live client. Allocation checks inject failures at each acquisition and verify cleanup of the three error-message buffers after a genuine SPICE failure. Real Chrome exercised all seven methods, both close modes, a surviving read alias and writer readback. The audited routines remain reviewed until source-bound required local and canonical CI evidence is recorded. [Per-routine scientific evidence](../data/parity-audits/e18-dsk-data.json)

The complete suite found two older workflows that write a DLA file through file I/O and inspect it through DSK. A DSK-only scratch prefix made the readers open the wrong path. Virtual scratch IDs now use the same case namespace across the workflow domains. The registered cases require the original INVALIDFILETYPE diagnostic from the actual closed DLA file.
