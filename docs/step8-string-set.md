# Parsing into a caller-owned character set

`raw.lparss(list, delims, set)` updates a live character cell from the same backend. Allocate it with `kit.newCharCell(maxCardinality, rowBytes)`, observe each member with `raw.card` and `kit.cellGetc`, and release it with `kit.freeCell`. The two string arguments contain UTF-8 bytes. Each destination row includes space for a terminating NUL. For nonempty lists, LPARSS replaces the existing members, sorts them and eliminates duplicate stored rows. Blanks and adjacent nonblank delimiters have different empty-item rules. [NAIF LPARSS](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/lparss_c.html)

The empty C list takes an early INSRTC path in N0067. It retains the old members and inserts the empty string, even if the delimiter string is empty. A nonempty list with an empty delimiter string signals a toolkit error before replacing members. The members fit by stored byte width. Two long items with the same truncated prefix collapse. Choose enough bytes for complete UTF-8 when reading back TypeScript strings. The kit accessor trims trailing whitespace for display. Inserting plain A after a parsed A with a trailing tab increases the cardinality, providing an independent observation of the retained tab.

LPARSS can change rows before it reports SETEXCESS. On an original two-member cell with capacity two, parsing `B,A,C` leaves the two rows `A` and `B` after the exception. Both backends reset the CSPICE error flag and permit reuse of this same cell. Translated Fortran control words require additional row width on the nonempty path. The native implementation locks the process-wide toolkit. WASM frees its error and two input buffers through the scoped allocator on every exit. Both validate caller ownership, string representation and the shared signed workspace bounds. The locked SpiceyPy high-level wrapper allocates a fresh result. The independent reference binds the same library's void canonical symbol with two C strings and a pointer to the workflow's persistent SpiceCell. It checks the toolkit error status after each call. Cases compare sorted members, replacement and insertion on a populated cell, ASCII delimiters and whitespace, intact multibyte tokens, truncation collisions, duplicate capacity, and specific toolkit capacity and width errors. The public tests also inspect post-failure content and the real worker exercises mutation, reuse and error recovery. All inputs are authored strings.
