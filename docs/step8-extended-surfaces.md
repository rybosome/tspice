# Surface grids, normals, limbs and terminators

E20 adds four raw geometry operations on top of E19's surface selection, bounded UTF-8 marshalling and DSK fixtures. Each Node handler holds the CSPICE mutex across the shared C call and error capture. WASM checks owned allocation sizes before entering the same shim. All four methods bypass the optional transport result cache because the loaded shapes, frame definitions and ephemerides affect results.

| Method   | Inputs and returned observations                                                                                                                                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `latsrf` | Target-fixed planetocentric longitude/latitude pairs in radians, returned as rectangular surface points in km. An explicit DSK surface list restricts the outermost radial intercept. A missing intercept can signal POINTNOTFOUND.                   |
| `srfnrm` | Outward unit normal at each point in the requested target-centered frame. The radial vector and normal generally differ on a triaxial ellipsoid. DSK cases use facet interiors with a unique normal, and an off-plate point checks POINTNOTINSEGMENT. |
| `limbpt` | Limb points from a finite observer, with one count per cutting half-plane, dense target-frame points, associated surface epochs and observer-to-point tangent vectors.                                                                                |
| `termpt` | Umbral or penumbral terminator about the finite source, observed from a separately specified body. The returned vectors are observer-to-point vectors. The illuminator, observer and target in the fixture have distinct NAIF IDs.                    |

Row order follows the input grid or angular cutting order. A cut with no solution has count zero. The dense arrays have length equal to the sum of all cut counts. Angles, angular steps and solution tolerances are radians, positions and vectors are km, and epochs are TDB seconds past J2000. Kernels are cleared and clients disposed after each test. Input arrays are snapshotted once, and every returned row is independently owned. The wrappers allow up to 11,184,810 rows per 24-byte result-vector buffer, within the 256 MiB transport limit. Negative or otherwise invalid scientific counts retain the toolkit's own error path through bounded non-null storage.

## Cut result capacity

The N0067 SPICELIB implementation of LIMBPT checks each cut against its initial MAXN. Both correction-locus branches leave that available-room value unchanged as they advance the destination row. Multiple points on one cut can therefore leave less space than the next check assumes. The shared shim calls the public `limbpt_c`. Both build paths stage the same hash-checked N0067 source and update the available count at each of its two existing checks to MAXN minus the already-written rows. This preserves the toolkit's geometry, OUTOFROOM message, error trace and early return before a cut that does not fit. The staging step refuses an unrecognized input source. Native builds use the platform release's source when present. Headers-and-archives-only native installs obtain the same hash-checked file through the existing pinned source cache or its downloader. The project distributes the small staging operation and compiles against the pinned toolkit under its existing distribution terms. [Source staging](../scripts/stage-limbpt.mjs)

The independent Python reference invokes the unmodified C routine in the locked SpiceyPy library. Its original 2,000-endpoint local cell bounds the number of results for one cut. For valid positive counts the reference reserves physical output space for every cut up to that bound and its individual MAXN check, then checks the returned counts. Scientific comparisons use sufficient logical capacity. A separate public test on the corrected implementation requires OUTOFROOM at capacity four, error reset, and a successful six-row result at capacity six for counts `[3,1,1,1]`. The corresponding TERMPT source deducts the cut count while copying each point, so the same geometry at capacity six can signal OUTOFROOM early. Its genuine diagnostic is compared independently. [Independent binding](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/surface_oracle.py)

SpiceyPy 6.0.3's public cut wrappers index output arrays with the positions of positive count entries. This can discard additional points or empty-cut counts. The sidecar binds each canonical C entry with SpiceyPy's typed declarations, reads every count and copies the complete defined dense prefix. For empty grids, typed non-null storage allows the actual zero-count call and its ordinary validation. Nonempty grids use the standard locked wrappers.

## WASM traversal stack

The optimized N0067 DSK ray traversal ZZDSKBUX reserves 88,336 bytes for a single automatic frame in the pinned Emscripten 3.1.74 build. The toolchain's default stack is 65,536 bytes. DSK tangent terminator results on two ordinary authored shapes disagreed with the locked reference. Both returned the reference counts and every dense output component after the build reserved a 2 MiB stack and enabled checks on each stack-pointer adjustment. The same link settings apply to browser and Node WASM. The capacity is a tested project configuration for these paths, and each checked adjustment enforces the runtime bound. ## Independent observations

The synthetic triaxial ellipsoid has semiaxes of 3, 2 and 1 km. Public checks compare each radial point to its input direction and each normal against the analytic gradient. For the ellipsoid limb, the observer-to-point vector is perpendicular to the gradient. For the terminator, the tangent plane's distance to the center of the unit-radius illuminator is one km. The cases independently exercise both correction loci, light time, stellar aberration, a rotated frame, reversed roll, surface selection, and umbral versus penumbral boundaries.

The authored DSK contains two separated closed octahedra on surface 103. Surface 104 contains only the off-center component. Selecting 103 gives three tangencies on the first half-plane and one on each remaining cut at ET zero. Selecting 104 gives `[2,0,0,0]` on the same tangent search. Guided cuts can differ. The fixture was generated by locked SpiceyPy from explicit project-authored geometry, with outward-oriented plates and no external mission data. [Fixture generator](../packages/py-parity-checking/fixtures/generate-surface-cuts.py)
