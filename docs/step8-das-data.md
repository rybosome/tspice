# DAS typed data reads and writes

C05 adds nine raw character, double and integer transfer operations in the existing file I/O domain. Every operation uses the matching N0067 C routine on an owner-validated DAS or DAS-backed DLA handle. The three address spaces grow independently. Logical addresses begin at one and include both endpoints. Character column indices begin at zero and include both endpoints. Native calls take the process-wide CSPICE lock after copying caller data. [Typed contract](../packages/backend-contract/src/domains/file-io.ts) [DAS required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/das.html)

| Data type              | Append                               | Read                                            | Update                                        |
| ---------------------- | ------------------------------------ | ----------------------------------------------- | --------------------------------------------- |
| Arbitrary bytes        | `dasadc(h,n,bpos,epos,datlen,bytes)` | `dasrdc(h,first,last,bpos,epos,datlen,initial)` | `dasudc(h,first,last,bpos,epos,datlen,bytes)` |
| IEEE doubles           | `dasadd(h,n,values)`                 | `dasrdd(h,first,last)`                          | `dasudd(h,first,last,values)`                 |
| Signed 32-bit integers | `dasadi(h,n,values)`                 | `dasrdi(h,first,last)`                          | `dasudi(h,first,last,values)`                 |

Append consumes the first `n` words. Zero or negative counts add no logical words. A successful update replaces the inclusive range of existing addresses. A read returns independently owned data. For character operations, `Uint8Array` supplies complete fixed-width rows. The caller can observe all original bytes outside the selected destination columns, including unused trailing bytes. A column may contain any byte, including NUL. Signed zero, both infinities and NaN are legitimate double data. NaN payload preservation is outside the JavaScript number contract.

## Logical ranges and physical records

Each data record holds one type and occupies 1,024 bytes. This holds 1,024 character bytes, 128 doubles or 256 integers. The C readers translate the first address before fetching data from physical records. The shim checks both endpoints against the file summary before dispatch. For an out-of-range endpoint it obtains the genuine error from DASA2L with that endpoint. This also prevents requests from reading unused space at the end of a physical record. The scientific cases compare valid reversed intervals inside one record. A reversed numeric read across physical records can produce a physical-index error when its computed final word falls outside the starting record.

DASUDC checks source columns differently after the first physical record. Its continuation loop compares the next one-based column to the substring **width**. With a nonzero beginning column, this can start a new source row early. For example, an update of addresses 1024 through 1027 with columns 2 through 3 and row width 5 reads byte indices 2, 7, 8 and 12. The shim accounts for that cursor and requires complete backing rows before invoking DASUDC. Independently allocated source rows in the live case distinguish those four values. [NAIF DASUDC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dasudc_c.html) [Source cursor case](../packages/py-parity-checking/src/cases/file-io/dasudc.cases.json)

The adapters accept signed 32-bit scalar positions and counts. Both transports cap each caller transfer buffer at 256 MiB. The shim checks address/cluster rounding, physical record numbering, platform seek bounds and the N0067 C-to-Fortran column increments before use. An empty transfer receives non-null sentinel storage. Genuine toolkit errors such as NODATA, NOROOMFORDATA, BADSUBSTRINGBOUNDS, INVALIDINDEX, INDICESOUTOFORDER, INVALIDADDRESS, DASNOSUCHADDRESS and DASINVALIDACCESS retain their ordinary meaning. Cases with malformed files or oversized requests are outside scientific acceptance. Existing close/flush behavior applies to buffered updates. ## Unused bytes of authored records

Each of the three pinned append implementations writes a complete physical record from a static work array when allocating a record. On a partial final record the unused suffix has no logical address. To give exported files deterministic padding, a successful append that allocated a new partial record locates its final logical address with DASA2L and zeros only the remaining physical words with the matching buffered DASURC, DASURD or DASURI. Physical records each belong to one typed cluster. No other allocated logical address can occupy that suffix. This adds no flush, touches no earlier record and runs only on the append that creates the partial record. A later append into that record overwrites only its newly allocated prefix. As with a toolkit write failure, an error during padding finalization can follow a logical state change. Discard an output whose writer reported a failure.

The public file test first writes whole typed records in an independent scratch file and then creates another file with three partial records. The locked reference opens the finished output, independently locates all three physical records, and checks the unused byte counts of 1,020, 992 and 1,008. This physical output policy is separate from the comparison of logical DAS data. [Bidirectional cross-file tests](../packages/py-parity-checking/test/das-data-public.test.ts)

## Independent observations

SpiceyPy 6.0.3 exposes all six numeric methods. Its ordinary reads and writes supply the numeric reference. Reversed numeric reads use the canonical symbol with initialized sentinel storage because their output array has no elements. For logical endpoint errors the reference passes the invalid endpoint as the first address so the toolkit diagnoses it before physical record access. The Python package lacks DASRDC and DASUDC wrappers. Its DASADC string adapter cannot represent arbitrary binary rows with independent row stride. Three typed bindings to the locked library pass the exact C signatures and independently owned binary storage. Each call checks the actual toolkit error state before interpreting output. [Independent oracle](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/das_data_oracle.py)

The 54 registered workflows contain 253 steps, 154 calls to these nine routines, and 21 expected terminal errors. All 108 live Node/WASM comparisons passed. Four public cross-file tests cover both directions between the actual backend and the locked library. The independent writer operates on a temporary copy of the existing project-authored DSK and appends unreferenced logical addresses, retaining valid segment metadata for ordinary FURNSH staging. Three native and 28 WASM adapter checks cover storage ownership, rejected transfers, handle ownership, read-once inputs, every allocation position and post-error reuse. Real Chrome exercised all nine through the public inline worker, with exact binary byte values, an unchanged initial destination, signed integer endpoints, updates to all three streams and address-error recovery.
