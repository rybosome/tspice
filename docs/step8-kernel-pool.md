# Kernel-pool validation, direct loads and continued strings

The nine B05 methods extend the existing kernel-pool contract. Both compiled backends invoke the matching N0067 CSPICE routine through the shared shim. All public integer inputs fit a signed 32-bit SpiceInt. Scalar string arguments and text rows use well-formed UTF-8 without embedded NUL. The by-value BADKPV type is a single ASCII byte. ## Caller storage and state

BODVCD and BODVRD return owned arrays of the reported dimension. The pinned pool holds at most 400,000 numeric components. The adapter supplies up to that many doubles, including a non-null sentinel for negative or zero requested capacity. CSPICE handles insufficient room and wrong-type or missing constants. Public tests exercise mutation independence and exact small values in caller units. [BODVCD](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/bodvcd_c.html) [BODVRD](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/bodvrd_c.html) [SZPOOL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/szpool_c.html)

LMPool snapshots each JS line once and computes its encoded byte length before allocating the rectangular rows. The stride includes a terminating NUL and is at least two. The signed row-count/stride product must fit the toolkit’s internal arithmetic. The WASM transport also limits each allocation to 256 MiB. N0067’s private ZZRVBF parser copies at most 132 bytes of each row. Loader errors can leave successful earlier assignments and watch notifications in place. [LMPOOL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/lmpool_c.html)

LDPOOL uses the backend’s path conventions. For a byte source, Node writes an owned snapshot to a private temporary directory and removes it after the call. WASM exclusively creates a temporary file outside the user’s virtual kernel namespace, then removes it on success or error. Neither loader uses FURNSH for this call. CLPOOL clears values while preserving watch registrations and the KEEPER inventory. The independent flows observe the inventory, watch state and readback. [LDPOOL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ldpool_c.html) [CLPOOL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/clpool_c.html) [DVPOOL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dvpool_c.html)

## Pinned-source bounds

STPOOL’s translated code computes the starting position of a suffix comparison using the trimmed byte lengths of the row and marker. When the marker is exactly one byte longer, the translated routine selects a comparison position preceding that row. Before dispatch for markers of two through 81 significant bytes, the shared shim reads bounded pages of components and checks only those the requested logical string would visit. Blank components have significant length one. A valid earlier logical string can still be read when a later component would fail this check. A negative ordinal, short output buffer or invalid empty input retains its normal canonical path. The single signed maximum ordinal maps to the adjacent, equally absent ordinal because N0067 adds one internally. A bounded output capacity of at most 1,200,001 bytes covers MAXLIN × MAXCHR and a terminator. The full size can exceed the short result. Both backends reject a UTF-8 code point cut by the returned C buffer. [STPOOL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/stpool_c.html) [Shared guard and direct call](../packages/backend-shim-c/src/domains/kernel_pool.c)

BODVRD can enter the private ZZBODKER → ZZBODINI → ZZHSIADD → ZZHASHI path while rebuilding external body mappings. The N0067 integer hash takes a signed absolute value. For a correctly typed, equally sized mapping pair within its 14,983-entry limit, the guard rejects a code that would round to the minimum signed integer. A code outside the accepted conversion range or a blank name in the effective 36-byte records gives the original CSPICE diagnostic before hashing. The guard applies to the mapping table, including duplicate names. Direct BODVCD integer formatting supports the entire signed range. Tests for the excluded boundaries invoke the corrected adapters or checked independent oracle. ## Scientific evidence

The registry has 69 workflows, 289 total steps and 164 invocations of these nine new routines. Thirty-two workflows terminate with genuine CSPICE errors. Both compiled backends passed all 138 registered live comparisons. Eight additional public tests cover exact value ownership, byte truncation and strict decoding, state and watch changes, scientific error recovery and defined diagnostic priorities. Focused wrapper checks include 18 Node tests and 34 WASM tests, including allocation failures at each acquisition. The non-DOM consumer compiles both facade types. Real Chrome exercised all nine facade methods through its inline worker and fetched WASM binary. Full source-local and canonical CI observations are recorded separately. [Public checks](../packages/py-parity-checking/test/kernel-pool-operations.test.ts) [WASM storage checks](../packages/backend-wasm/test/kernel-pool-operations.test.ts)

The independent sidecar calls SpiceyPy 6.0.3 or canonical symbols from that installation’s separate N0067 library. STPOOL caller-owned bytes preserve returned whitespace and the pre-truncation size. LMPOOL uses direct canonical buffers for zero/blank or UTF-8 row representations its convenience wrapper cannot faithfully represent. Nonpositive body output capacities use actual C calls with initialized sentinel storage, preserving toolkit errors before Python array conversion. Other operations use the ordinary checked locked wrappers. The repo supplies synthetic successful and partial-error text kernels and constructs other pool values in memory.
