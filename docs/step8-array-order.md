# Array ordering and permutations

All eleven raw methods live in the existing coordinates-and-vectors domain. Both backends own their inputs during the call. A returned array can be mutated without changing input or a later result. The character and integer adapters reuse the validated array snapshots introduced in [sorted bounds](step8-sorted-bounds.md).

| Methods                                | Input                                                                         | Result                                                                                                                                                               |
| -------------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `isordv`                               | Signed 32-bit indices                                                         | Whether a nonempty array contains each integer from zero through its length minus one exactly once. Empty input returns false.                                       |
| `orderc`, `orderd`, `orderi`           | Strings, doubles or signed integers                                           | Zero-based source indices in the order produced by CSPICE.                                                                                                           |
| `reordc`, `reordd`, `reordi`, `reordl` | A permutation followed by equally many strings, doubles, integers or booleans | An owned data array whose entry at destination `i` comes from source `order[i]`. The indices must be distinct and in range. Two empty arrays return an empty result. |
| `shellc`, `shelld`, `shelli`           | Strings, doubles or signed integers                                           | Data values sorted by the toolkit on a private copy.                                                                                                                 |

The Shell sort starts with a gap of half the length and repeatedly halves it. Tied entries can change relative order. For example, `orderi([1, 0, 0, 0])` yields `[2, 1, 3, 0]`. A double can be infinite, NaN, either sign of zero, or subnormal. CSPICE’s comparisons determine its output. No total ordering is defined for NaNs. The tagged oracle compares full permutations, a NaN category, and the exact IEEE representation of each other double, including signed zeros. [Numeric ordering](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/orderd_c.html) [Numeric sorting](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/shelld_c.html)

Character rows contain UTF-8, have no embedded NUL and share a byte stride of at least two. ORDERC compares unsigned bytes under blank extension. It receives rows padded through the byte before the final NUL. This gives N0067’s conversion workspace positive width even if every input string is empty. REORDC preserves the original C string in each row, including leading BOM, tabs and trailing spaces. SHELLC returns a singleton unchanged and trims trailing ASCII spaces when converting sorted Fortran rows back to C for two or more entries. A terminal tab survives. [Character ordering](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/orderc_c.html) [Character reordering](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/reordc_c.html) [Character sorting](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/shellc_c.html)

The maximum size of each native buffer is 2,147,483,647 bytes. Each WASM buffer is limited to 256 MiB. Count, byte stride, stride times count, and permutation bounds are checked before the relevant allocations or toolkit writes. ISORDV converts zero-based entries by adding one in a signed integer. Any input equal to the largest signed integer lies outside the supported permutation range. The shim substitutes an impossible negative index in the owned buffer before calling the predicate. Each reorder requires a valid order, including singleton input. The independent shim guard validates indices before the toolkit’s gather or cycle traversal. [Order predicate](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/isordv_c.html)

## Observations

The locked SpiceyPy 6.0.3 wheel supplies the independent N0067 library. A private ctypes binding declares each C signature, provides non-null physical storage for empty arrays, and reads returned bytes through the first NUL. It checks CSPICE status after each call. A separate control compares all eleven bindings against the ordinary SpiceyPy wrappers on shared representable data. The high-level wrapper trims terminal spaces and tabs while converting character results. The byte-preserving route retains the canonical C results. [Independent oracle](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/array_order_oracle.py) [Public and exact IEEE tests](../packages/py-parity-checking/test/array-order.test.ts)

The 63 registered workflows make 147 operation invocations. Of these, 135 call the independent library and twelve verify that malformed permutations are rejected before the scientific call. The compiled Node and WASM backends passed all 126 registered comparisons, five public and oracle tests, 24 native adapter tests, and 43 WASM tests. The WASM tests inject failure at 30 acquisition points and check cleanup and recovery. A real Chrome worker exercised all eleven methods, including recovery after an invalid permutation. The per-routine audit also records the inherited A24 dependency. Full source-bound local and canonical CI observations belong to the delivery record.
