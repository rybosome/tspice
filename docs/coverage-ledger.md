## Evidence and limits

TypeScript's compiler API resolves the composed raw contract, parses returned backend API objects, and follows local helper calls. A balanced-token C/C++ index traces native registrations and shared shim definitions while excluding comments and literal contents from call detection. WASM routes must have typed exports, build-configured exports, and exports in the checked-in binary. The registry evaluator accepts static imports, identifiers, type assertions, arrays, and spreads and rejects unsupported syntax. Qualified workflow operations must exist in the dispatcher; cross-domain aliases additionally require a direct raw-method call in the matching domain handler. The JSON records these aliases with source evidence.

These are static evidence checks, not a semantic audit or an observation of a successful CI run. `same-named-cspice-entrypoint` means the traced shim graph contains that entrypoint; wrapper normalization, validation, state, and composed behavior still require review. Referenced paths distinguish checked-in fixtures, generated outputs, scratch paths, and missing/negative-test references. Path requiredness is unaudited.

Configured CI lanes come from [.github/workflows/ci.yml](../.github/workflows/ci.yml).
