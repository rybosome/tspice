# Coordinate Jacobians

These twelve raw methods return nine owned row-major components, with output-coordinate index increasing by row and input-coordinate index increasing by column. Longitudes, latitudes, azimuths, elevations and colatitudes are in radians. Radius, altitude and Cartesian axes use the caller’s common length unit. `Mat3RowMajor` uses the IEEE-preserving result constructor from [#712](https://github.com/rybosome/tspice/pull/712). ## Coordinate charts and conditioning

For example, `dcyldr(3, 4, 12)` has rows approximately `[0.6, 0.8, 0]`, `[-0.16, 0.12, 0]` and `[0, 0, 1]`. Reversing azimuth direction changes the azimuth derivative, and reversing positive elevation changes the elevation derivative. Cylindrical, latitudinal and spherical forward derivatives accept signed radius. The azimuth/elevation forward derivative rejects negative range. At zero radius the forward angular derivative columns vanish. The reverse Jacobians signal POINTONZAXIS on the axis or at the origin. Close to a singularity the inverse angular derivatives can be very large. [NAIF DRS/DAZEL derivatives](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/drdazl_c.html)

The two geodetic derivatives and the planetographic pair take equatorial radius and flattening from the caller. Negative flattening describes a prolate spheroid. Altitude can be negative. The body selects planetographic longitude sense. Earth normally uses east, and an explicit BODY<id>_PGR_POSITIVE_LON override can change that. Other bodies require either the override or a prime-meridian rate. The pinned routine accepts zero rate and assigns the same default longitude sense as a positive rate. After a successful lookup for the Sun and Moon it selects east. Both planetographic directions observe changes to body mappings, spin and overrides between calls. The registered tests set their own synthetic pool values and release pool state using the existing case lifecycle. [NAIF planetographic convention](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dpgrdr_c.html)

## N0067 error paths

All production adapters invoke the matching public CSPICE routine for its scientific matrix and transfer the result only after checking the error state. The outer C wrappers transpose caller-provided output after the translated routine returns, including several error exits. The shim initializes all nine physical output doubles before calling them. Separate JavaScript validation covers finite numeric inputs, strict direction booleans and representable NUL-free body names. Returned doubles preserve signed infinities and NaNs. [Shared C adapter](../packages/backend-shim-c/src/domains/coords_vectors.c)

Two paths have narrower preconditions in the pinned implementation.

- The planetographic Fortran entries supply an uninitialized body ID to ZZBODS2C. That cache routine unconditionally copies the supplied integer even after a failed name resolution. The adapter resolves names first into initialized storage, retaining the underlying body lookup error if it signals and issuing the original Jacobian IDCODENOTFOUND diagnostic on a clean miss. It also screens valid paired NAIF_BODY_NAME/NAIF_BODY_CODE tables for the signed minimum, which N0067 cannot hash. Earlier errors in malformed tables take their normal precedence. A table guard regression exercises the corrected adapter and then replaces the value and resumes. The independent oracle uses a separately bound copy of the locked library and its own BODS2C found flag for unknown names. This diagnostic is an explicitly composed exception path. Ordinary science uses the actual DPGRDR and DRDPGR.
- DGEODR calls RECGEO, which calls NEARPT and SURFNM before passing its private surface normal to error-free RECLAT. A failed NEARPT can leave that normal unwritten. The adapter calls the actual NEARPT into initialized storage first and propagates its original failure with the DGEODR/RECGEO trace. A nonfinite computed polar radius or an unrepresentable reciprocal of the smallest positive reference axis is rejected before nearest-point scaling. DPGRDR first resolves its longitude policy on an ordinary unit reference point to preserve the ordering of body and geometric errors. No check substitutes for the returned Jacobian. The independent oracle calls SpiceyPy NEARPT before the problematic parent path. [Independent source adapter](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/jacobian_oracle.py)

The audit uses 80 registered workflows with 190 steps, 168 new-method calls and 31 expected diagnostic exits per backend. Both compiled backends passed all 160 comparisons. Six supplemental public tests compare every derivative in both directions against independent coordinate transforms evaluated with two central-difference step sizes, check both orders of the inverse product on well-conditioned points, and match all nine IEEE classifications and finite components at extreme forward inputs. Central differences have a separate 2e-8 scaled bound; the registered scientific comparison retains its usual tolerance. Twelve native boundary tests and 38 compiled WASM allocation/recovery tests passed. The sync/async no-DOM consumer compiled.
