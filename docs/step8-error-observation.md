# Prepared diagnostics and traceback observation

Seven methods on the raw error API expose CSPICE’s process-local diagnostic state. They need no kernels. Node serializes each call through its existing CSPICE lock. A WASM client reads its own toolkit instance. A sequence of calls can span other activity that shares the native process. [Error required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/error.html)

| Method   | Effect or result                                                                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `errch`  | Replace the leftmost nonblank marker in the prepared long diagnostic with a character field. Blank replacement inserts one space, and the toolkit applies its 1840-byte field width. |
| `errdp`  | Substitute a finite double into the prepared message with the exact N0067 14-significant-digit diagnostic rendering.                                                                 |
| `errint` | Substitute a signed SpiceInt into the prepared message, including both endpoints and zero.                                                                                           |
| `qcktrc` | Observe the printable current traceback, or the frozen traceback while an error is pending. Explicit byte capacity includes NUL.                                                     |
| `return` | Read the immediate-return indicator. With the backend’s RETURN action it is true exactly while failure is pending.                                                                   |
| `trcdep` | Read the logical depth of the current or frozen traceback, including overflow entries beyond the 100 stored names.                                                                   |
| `trcnam` | Read one zero-based module name, bounded by caller byte capacity. Observe legitimate overflow placeholders and genuine index and capacity errors.                                    |

Use `setmsg` before the substitutions and `getmsg("LONG")` to read the complete prepared text. Markers and character replacements are UTF-8 byte strings. Leading and trailing ASCII blanks are removed from the substituted field. The blank and empty cases differ. Numeric replacements preserve CSPICE’s decimal formatting, including exponent notation. The first occurrence changes, even when another identical marker follows. A captured `sigerr` carries the substituted message on its structured exception and clears the error before it reaches JavaScript. [Public raw contract](../packages/backend-contract/src/domains/error.ts)

`qcktrc(tracelen = 4096)` can hold the hundred 32-byte names, separators and overflow text produced by N0067. `trcnam(index, namlen = 33)` returns the individual stored name or the toolkit’s overflow placeholder. Both honor a smaller caller capacity, including the original STRINGTOOSHORT diagnostic. Both preserve significant trailing non-space bytes and reject a partial UTF-8 code point. The locked SpiceyPy convenience decoder ignores malformed bytes and removes trailing whitespace, so these two reference calls bind its actual void C symbols with explicit buffer lengths and decode their output strictly. [Locked-library dispatch](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/handlers/error.py)

When a failure is pending, CSPICE’s RETURN action freezes the trace and prevents further long-message changes. A bad trace index or too-small output capacity replaces the pending diagnostic by design. The raw JavaScript boundary normally captures and resets every error immediately. A standalone native and WASM test signals a failure directly through the linked toolkit before using the same production shim to observe `return() === true`, the frozen names, inhibited substitutions and replacement error. Registered JavaScript workflows use ordinary signaling and verify the post-capture false state. [Pending-state test](../packages/backend-shim-c/test/error-observation.c) [Public behavior](../packages/py-parity-checking/test/error-observation-public.test.ts)

The registered workflows check prepared text and exposed traceback values directly. They include repeated markers, exact numeric formatting, both signed integer limits, 1840-byte exhaustion, depth/overflow annotations, UTF-8 byte capacities and original toolkit errors. Each managed trace is unwound on success or failure. The 100-name overflow cases can emit the toolkit’s direct storage-full notice while still returning the correct depth and names. Four public tests, one private native test, 22 real WASM tests and an isolated real Chrome worker exercise representation, allocation cleanup, signal capture and recovery. The only fixtures are authored names, numbers, and strings. [Per-routine record](../data/parity-audits/b06-error-observation.json)
