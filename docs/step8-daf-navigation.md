# DAF search state and packed summaries

An open DAF claim identifies a file. CSPICE keeps one saved search position per file and a current search for the toolkit instance. Starting a backward search places the cursor just after the last array. A successful previous step positions it on an array. Stepping past the first array returns false and clears the current array. The search can still be selected, advanced in the other direction, or restarted. Selecting a file whose search has never begun raises `SPICE(DAFNOSEARCH)`. [DAF required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/daf.html)

The native backend holds its shared CSPICE lock across each handle-scoped selection and operation. Repeated read opens create distinct public tokens but share the native file handle and cursor. `raw.dafgh()` looks up the oldest surviving DAF token for the selected native handle in the calling backend. Closing that claim promotes any surviving local alias. A different Node client with its own alias can retrieve only its own token. A client with no matching claim receives an error. A successful write open receives a separate owned claim. A registration failure closes the just-acquired writer. [Native ownership tests](../packages/backend-node/test/daf-navigation-domain.test.ts)

## Previous-array call

The N0067 implementation of `daffpa_c` declares a private `logical fnd`, calls `daffpa_(&fnd)`, then unconditionally reads `fnd` into the caller's output. SPICELIB can return before assigning that local on failure. The shim first selects the handle with `dafcs_c`. On success it enters the same outer `daffpa_c` trace frame, calls the linked `daffpa_` exactly once with initialized storage, checks out, and examines toolkit status before publishing the result. The compile-time width check, pinned `SpiceZfc.h` declaration, linked native symbol and generated WASM exercise establish the ABI. The ledger tracks this explicit alias on both routes and requires the linked call, selection and outer trace. ## Names and binary layout

`dafgn(handle, namlen)` accepts a signed 32-bit byte capacity including the terminating NUL. The default 1001 accommodates a maximum-size DAF name. The adapter bounds larger positive lengths to 1001. It provides a valid byte of storage for smaller nonpositive capacities so the real toolkit can check them. Selection occurs first. Lengths below two on an active search raise `SPICE(STRINGTOOSHORT)`. The toolkit strips trailing blanks in its C conversion. Its remaining UTF-8 bytes are decoded strictly, preserving a terminal tab or initial BOM. A truncated multibyte character cannot produce a JavaScript string. The independent oracle reads the checked C byte buffer because the high-level Python conversion strips trailing whitespace. [DAFGN reference](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dafgn_c.html)

`dafhsf(handle)` returns the numbers of double and integer summary components for an open file, including a file with an empty or exhausted search. `dafgs(handle)` copies exactly `8 * (nd + ceil(ni / 2))` bytes into a new `Uint8Array` in native byte order. N0067 permits up to 124 double and 250 integer components in a maximum of 125 double words. The shared C shim reserves the full 125 words for the capacity-free CSPICE call. The sidecar copies the NumPy array's bytes. Negative integer components can make an entire packed word appear to be a NaN when viewed as a double. The public assertions compare every byte, including both integer halves, address words and the NaN payload. [DAFGS reference](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dafgs_c.html) · [Binary RPC regression](../packages/tspice/test/daf-summary-rpc.test.ts)

## Fixture and runtime evidence

The registered searches use repository-authored SPK, empty DAF and CK files. Writer workflows create and close a synthetic type-8 SPK in case-local scratch storage before opening it for write. Each lifecycle closes outstanding claims and removes its physical scratch directory. A live WASM module retains its MEMFS files until disposal. Repeated writer cases use a distinct run directory and share the corresponding path among generated-file consumers. The separate public fixture creates a new SPK from invented states and IDs through locked SpiceyPy, renames its array with SPICELIB DAFRN to preserve a terminal tab, and obtains its expected 40 summary bytes from that same library. Its generator refuses to overwrite an existing file.
