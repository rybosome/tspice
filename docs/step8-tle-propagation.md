# Two-line elements and SGP4

`raw.getelm(firstYear, lines)` takes an ordered pair of ASCII records and returns the TDB epoch (seconds after J2000) and ten elements. The array contains NDT20 in rad/min², NDD60 in rad/min³, BSTAR with its implied exponent applied, inclination and node in radians, eccentricity, argument of periapsis and mean anomaly in radians, mean motion in radians/minute, and the same epoch. The two-digit epoch year expands using the first year of the caller's century window. The fractional epoch day uses UTC. [GETELM](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/getelm_c.html)

`raw.evsgp4(et, geophs, elems)` returns all six Cartesian state components in **TEME**, km and km/s. Its input epoch and evaluation time both use TDB seconds after J2000. Supply the constants in J2, J3, J4, KE, QO, SO, ER, AE order. The harmonics are dimensionless, KE uses Earth radii to the power 3/2 per minute, and the atmospheric heights and radius use km. N0067's initialization uses the fixed atmospheric values 78 and 120 km, and hardcodes unit Earth radius normalization. Both calls require an LSK. In EVSGP4, the initialization converts the **element epoch** to Julian date UTC before calculating the state. [EVSGP4](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/evsgp4_c.html)

The near-Earth survey, synchronous relay, nonresonant medium orbit and high-eccentricity half-day orbit span distinct initialization and propagation branches. ## Representable inputs and bounded integration

The public parser snapshots both NUL-free ASCII records before allocation. Its rectangular table is bounded to 256 MiB. N0067's ZZGETELM compares both six-byte vehicle IDs before checking the record lengths. Right-padding rows shorter than seven bytes with spaces keeps that comparison readable and preserves the toolkit's blank-padded field and nonblank-length semantics. The C conversion owns its temporary storage. The native call runs under the backend's CSPICE mutex; the WASM adapter frees its four work buffers on every exit.

The pinned UTC-day conversion casts the day and constructs its Gregorian day number in signed 32-bit arithmetic. The adapter supports first years from −5,000,000 through +5,000,000 and absolute parsed day fields through 300,000,000. These conservative bounds leave room for intermediate calendar and reference-day arithmetic. It delegates the 12-byte day field to the original NPARSD. If an otherwise parsed date exceeds a bound, a safe surrogate calendar argument preserves genuine earlier record or missing-kernel errors. If the toolkit accepts that surrogate, the wrapper reports its calendar-domain error. No returned epoch or elements come from the surrogate.

EVSGP4 limits the absolute input **element epoch** to 1.6×10¹⁴ TDB seconds to keep TTRANS and the sidereal-time helper's signed day counts representable for an ordinary LSK. An extreme evaluation offset on a resonant orbit has a separate computational boundary. Only the resonance branch of ZZDSPC iterates once per elapsed 720 minutes. An absolute interval of at least 43,200,000,000 seconds would require at least one million such steps. For these intervals, the shim queries N0067's ZZINIL for the corrected mean motion and applies ZZDSIN's synchronous and eccentric half-day conditions. The sidereal-time output in this classification is unused. The traced XXSGP4I initialization preserves any preceding toolkit error, and the adapter rejects the excessive resonant integration. Near-Earth and nonresonant deep-space evaluations still call EVSGP4 directly. The public test compares their six actual components with the independent runtime past the bound. A relative 1e−6 allowance is confined to this millennium-scale guard control; the separate within-days propagation cases use the ordinary 1e−12 comparator. No scientific accuracy over that long interval is inferred. ## Validation

The batch adds 23 registered scenarios and 58 calls to the new operations across 80 workflow steps. Nine scenarios terminate in a genuine toolkit error, and four additional errors are captured before recovery. Supplementary coverage includes seven public tests (one checksum test and three per backend), four Node tests including the real compiled addon, and eleven real-heap WASM tests including each routine's four allocation-failure positions. The real Chrome inline worker compares both epochs, all ten elements and all six propagated state components for the survey and relay records, then verifies the missing-LSK error and recovery. The Chrome check passed again on regenerated WASM SHA-256 `80f8158200aa80978403bc7f2a1229599fd8c1a2f603c0f7acc8f8c45289e5a8`. The initial registered recovery scenarios surfaced that the ephemeris dispatcher handled captured errors only for existing operations. The two new operations now preserve the toolkit's short error code and continue the workflow. Full required source-bound local runs and inspected canonical CI are recorded separately.
