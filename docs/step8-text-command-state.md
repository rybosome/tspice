# Text record reading and command initialization

C14 adds `raw.rdtext(file, lineln = 1024)` and `raw.putcml(argv)` to the existing file-I/O contract. Both run against N0067 on Node and WASM. The method signatures preserve the underlying cursor and command state. [Contract](../packages/backend-contract/src/domains/file-io.ts) [RDTEXT_C](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/rdtext_c.html) [PUTCML_C](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/putcml_c.html)

## Reading records

`rdtext` returns `{line, eof}`. The capacity includes the terminating NUL. A successful call consumes one complete formatted record even when only its first bytes fit. The C conversion removes trailing ASCII spaces. The tested N0067 f2c reader preserves leading spaces, a UTF-8 BOM, rightmost tabs and a carriage return before LF. A blank physical line gives an empty string with `eof: false`. EOF gives an empty string with `eof: true`, closes the file, and permits restart on the next call. With the authored unterminated last record and a wider output buffer, the actual formatted read returned EOF without that record. The TypeScript boundary decodes strictly. If a capacity splits a UTF-8 character, decoding throws after the successful native read has advanced the cursor. Input C strings must be well-formed and NUL-free. Output capacity is signed 32-bit with a 256 MiB transfer ceiling. The resolved filename fits the toolkit's 255-byte field. [Registered bytes, widths and EOF comparisons](../packages/py-parity-checking/src/cases/file-io/rdtext.cases.json)

A byte-backed source gets a private physical path until client disposal. The same client can continue reading with its virtual name. Conflicting bytes for that name are rejected before consuming another record. Multiple native clients reading the same ordinary physical filename share its actual cursor. Each has its own claim. EOF, a toolkit close or the last owner's disposal releases the reader. A separate WASM module owns its own toolkit state. An open reader survives kernel clear. Native operations and unit release run under the process-wide CSPICE mutex. C14 hash-checks the pinned definitions in `inquire.c`, `rdtext.c` and `rdtext_c.c` before staging narrowly checked replacements. The Fortran translation checks GETLUN failure before opening the selected unit and invalidates its saved filename when switching or closing, since both paths can change its saved index. Successful reads expose the selected reader unit to internal ownership bookkeeping, including when another toolkit unit has the same filename. Explicit last-close uses the original unit-close and table-removal code. Failures preserve the original toolkit status, message and call chain. ## Command arguments

`putcml` takes the entire argument vector including the executable name. The array length is `argc`. Empty vectors, empty entries, distinct UTF-8 arguments and surrounding whitespace pass intact. The linked toolkit copies the data. Its state outlives client disposal, error reset and kernel clear in a native process. Each fresh WASM module may initialize separately. A repeated initialization signals `SPICE(PUTCMLCALLEDTWICE)`. The public return is void. Immediately after a successful setter, the private compiled path reads back the canonical argument data and compares every byte. Only the setter is published. The toolkit owns successfully initialized command data for its lifetime. [Command workflows](../packages/py-parity-checking/src/cases/file-io/putcml.cases.json)

## Independent evidence

The sidecar uses a separately typed handle to SpiceyPy 6.0.3’s N0067 library. The locked high-level record conversion strips significant trailing whitespace, and its declared argument-vector pointer does not express the required `char **`. The oracle reads the canonical C buffer and Boolean directly. It establishes a separate read-only SPICELIB unit before the first original RDTEXT for each connected file. This gives the original inquiry a valid unit. RDTEXT still opens and advances its own reader. The independent witness is closed immediately after that call. Subsequent reads continue on the actual RDTEXT unit and cleanup consumes EOF before scratch removal. Empty-name and short-buffer errors are returned by the canonical C checks before original Fortran I/O. Missing-file and exhausted-unit recovery use the corrected compiled runtimes, with the pinned source as the error reference. Independent command cases overwrite caller storage after the locked setter, then compare count and each stored argument through the correctly typed private getter. Every native setter workflow runs in its own process.
