# Streaming variable-interval type 14 SPKs

`raw.spk14b(handle, segid, body, center, frame, first, last, degree)` opens a segment on an owned SPK writer. `raw.spk14a(handle, count, records, epochs)` adds one or more complete packets. `raw.spk14e(handle)` ends the segment, leaving the writer available for another segment. Close the writer with `spkcls` before reading a virtual output.

Each record starts with its time midpoint and radius in TDB seconds. Six groups of `degree + 1` Chebyshev coefficients follow for X, Y, Z in km and VX, VY, VZ in km/s. Each velocity component has its own polynomial. Each reference epoch marks the start of a record. The toolkit selects the later record at an exact transition. Record widths are fixed within a segment, while time intervals may differ. ## Ownership, interruption and recovery

The native addon serializes access to CSPICE. Its C shim tracks successful begins by physical handle, including packet width and cumulative accepted packet count. Each public client also checks its opaque token. WASM keeps the same native state per module. Both adapters snapshot finite record and epoch arrays once, with a 256 MiB combined limit. C checks their physical lengths and signed DAF address arithmetic before indexing. The largest accepted degree for representable format arithmetic is 357913939. The per-batch memory bound applies even when that theoretical degree would permit a valid descriptor.

Overlapping streams on different handles work. Each add and end explicitly selects its physical array through the linked DAFCAD entry, because an ordinary writer on another file can change DAF’s current array independently of the generic writer’s cached handle. SGSEQW retains a global index as well as the last generic handle. After ending a segment, the cached handle can continue to refer to the removed slot. Its begin lookup can also update that index on a failing call. The shim guards attempts that could disturb a different active stream, including an add/end on an inactive handle, a duplicate begin on a different active handle, and exceeding twenty active generic writers. Duplicate begin on the currently selected stream reaches the ordinary `CALLEDOUTOFORDER` error. With no streams active, out-of-order add/end calls also use the real routine and error trace.

Callers can correct rejected, non-increasing epochs on an active segment. SGWFPK checks the entire supplied epoch sequence before it writes those packets, leaving prior successful batches intact. Explicit close or a different complete segment writer on the same streaming handle requires an end first. Native client disposal ends each owned stream before closing it. It finalizes accepted packets, including an empty segment when no packets were accepted. A physical file test reads the actual state left by a disposed writer, then exceeds twenty successive interrupted streams to check slot release. The regular workflow finalizer also ends outstanding type 14 segments before closing handles. [Native lifecycle tests](../packages/backend-node/test/spk-streaming-domain.test.ts) · [WASM allocation tests](../packages/backend-wasm/test/spk-streaming-allocations.test.ts)

The type 10 writer from PR #763 and the type 14 writer share the same SGBWFS table. A type 10 write on the active type 14 handle requires an end first. A complete type 10 segment can be written to another file while the first stays open. With an active stream, the adapter checks generic slot capacity and the new file’s identifier before SGBWFS can disturb the saved index. The mixed workflow writes both segments, closes the type 10 file between type 14 additions and independently reads their orbital states and descriptors. The public regression also tries an invalid type 10 identifier, an unknown frame, unordered TLE reference epochs and a rejected type 14 reference, then writes to both handles successfully.

## Scientific evidence

The locked SpiceyPy 6.0.3 writer adds two degree-one packets in one batch. Each tspice backend writes the equivalent data in two batches, then an empty metadata-only segment. Independent readers inspect exact DAF addresses, segment identifiers, packet coefficients, duplicate reference table and all 17 generic metadata words. The four independent file exchanges compare complete physical records. Both real backends also read the Python-authored file and agree exactly with six manually evaluated polynomial components at six epochs. A 102-packet workflow crosses the 100-reference directory threshold. [Independent file reader and writer](../packages/py-parity-checking/test/_helpers/spk_streaming_oracle.py) · [Public tests](../packages/py-parity-checking/test/spk-streaming-files.test.ts)

N0067 SPKPVN has a 198-word evaluation buffer. A degree-31 record requires 195 words including its leading constant and evaluates successfully. A degree-32 segment is writable and physically complete, but querying it raises `SPICE(SPKRECTOOLARGE)` before packet extraction. A negative time radius is retained as supplied. An empty segment retains descriptor and coverage information and is inspected without requesting absent state data.

All 33 registered workflows passed on both compiled backends. Their 283 steps include 112 begin/add/end invocations and one inherited type 10 writer call. Writing and reading produced 21 expected toolkit errors. A real Chrome worker exercised begin, add, a genuine ordering error, corrected add, end, and close. Its six-component states agreed with the independent library at both boundaries and two additional epochs.

On the combined binary, Chrome also rejected four mixed-writer errors, recovered both writers and reloaded both physical files. The six-component type 14 state at ET 4 and the six-component type 10 state at ET 1 agreed with the independent results, and CSPICE reported a clear final error state.
