# DAS comment records

The three raw methods operate on client-owned DAS and DLA handles. A DAS file header identifies the allocated number of comment records (`ncomr`) and the number of comment bytes used (`ncomc`). Each 1024-byte physical record holds comment bytes starting at file record `nresvr + 2`, using one-based record numbering. Each row ends with a zero byte. The used-byte count locates the end. [NAIF DAS required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/das.html)

| Raw method                             | Inputs and result                                                                                                                                                                                        |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dasac(handle, lines)`                 | Append an ordered array of printable ASCII rows to a writable file. Leading and internal spaces are retained. Trailing spaces are removed. Empty and entirely blank rows each contribute one terminator. |
| `dasdc(handle)`                        | Delete every allocated comment record, including unused reservations. Repeating deletion on a writable file with an empty area succeeds.                                                                 |
| `dasec(handle, bufsiz, buffln = 1024)` | Read at most `bufsiz` rows. Each output slot has `buffln` bytes including the NUL. Return an owned `{n, lines, done}` with exactly the defined rows. The next extraction after EOF restarts at row one.  |

Appending beyond the reserved area grows the file and shifts later data records. Deletion reclaims these physical record positions. The file's logical character, double and integer addresses remain stable, and the byte length of the underlying file can retain its former high-water mark. [DASAC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dasac_c.html) [DASDC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dasdc_c.html)

## Defined arguments and diagnostics

The adapters take a single snapshot of the input strings and encode a rectangular NUL-terminated table. A blank input row is represented by a single space for the original CSPICE character conversion. Positive table and page byte extents must fit 256 MiB. Signed integer counts and widths reaching CSPICE preserve its validation order. The toolkit reports `INVALIDARGUMENT` for zero input rows or a nonpositive page count, `STRINGTOOSHORT` for an output width below two, `DASINVALIDACCESS` for changing a read claim, and `ILLEGALCHARACTER` for a tab, DEL or non-ASCII payload. Embedded NUL and malformed UTF-16 are rejected during representation. The scientific comparator checks strings, counts and booleans exactly. [DASEC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dasec_c.html)

One native process shares its DAS reader positions across clients. Tokens remain local to each client. Opening a read file twice creates two owned claims on the same underlying position. Closing one retains the other. Finish a writable file's partial extraction before changing its area, or close and reopen it for mutation. Otherwise N0067's saved positions would refer to old record contents. Independent files can be read in alternating order. The C shim tracks the original link count for each native file and drains an outstanding original extractor on final local close. Cleanup reads at most 64 rows per page, with a 256 MiB allocation bound. Header, byte-position and file-seek arithmetic are checked before record access.

## Pinned source and oracle

N0067's public `dasec_c` copies its private completion flag after an early inner error. The adapter runs the pinned SPICELIB `dasec_` with initialized outputs and the original outer trace. It converts the defined output rows using the linked `F2C_ConvertTrStrArr`. A successful read of a closed-and-reopened file is also tested against ordinary `spiceypy.dasec`. The sidecar uses an independently linked, locked CSPICE N0067 through SpiceyPy 6.0.3. It reads its own files and handles. [Locked environment](../packages/py-parity-checking/sidecars/spiceypy/uv.lock) [Independent DAS reader](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/das_comment_oracle.py)

The original extractor only frees a saved slot at EOF. A failure after crossing a physical record can change its process-wide cached bytes before committing the per-file position. A bounded scan uses the actual DAS unit and `dasioc_` record reader to establish whether the page fits before touching that cache. The original short-buffer diagnostic labels the page-relative row number as a line length. The adapter retains the original short message, long message and traceback. A caller can retry with a wider line while other files retain their positions. The independent sidecar can use the actual linked extractor on safe initial short-buffer errors and preserves the pinned diagnostic before a later-record failure.

The extractor also uses native ID −1 as its internal no-cached-record sentinel. DDH can assign that ID to a legitimate first write open. For that nonempty file alone, the adapter reads the named DAS records, follows their NUL row terminators and original header extent, and calls the original row converter. Ordinary handles run the linked extractor. The independent sidecar consumes an unused first handle before operating on its own writable files, so its scientific reference uses the actual ordinary reader. [Shared DAS implementation](../packages/backend-shim-c/src/domains/file_io.c)

A pristine unnamed `dasops` file can lack a recognized architecture ID before any named file initializes the toolkit's stored ID word. The first registered run exposed this fixture dependency in both lanes. The ordinary scratch success workflow now creates and closes a named DAS first. Separate fresh-process tests compare the `UNKNOWNFILARC` diagnostic and full call tree for both append and extraction, followed by a clear failed flag. A header preflight yielding that error delegates to the requested native operation for its exact trace.
