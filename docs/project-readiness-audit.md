- CI JS checks: Ubuntu and macOS, Node 20 and 22. The workflow fetches CSPICE and sets up `uv`; the root JS required command excludes the Node backend package itself.

Add this variable to the Turbo environment allowlist in step 6; see [Turborepo's environment mode documentation](https://turborepo.dev/docs/crafting-your-repository/using-environment-variables).

- Docs build and generated LLM artifact check: Ubuntu, Node 22.
- Release packages: macOS arm64, macOS x64, and Linux x64 glibc. No Windows or Linux ARM64 native package is currently present in the repo matrix.
- Python/SpiceyPy is used by `packages/py-parity-checking`; the CI reusable workflow installs `uv`, but the sidecar itself requires Python 3.11 or later.
- `format:check` currently expands to `pnpm -r --if-present format:check`; `lint` runs `lint:jsdoc` plus `pnpm -r --if-present lint`. No workspace package manifest declares either task, so only the JSDoc lint portion has an active target. This is a confirmed gate gap from repository config.

## 4. Audit decisions and next evidence

1. **Do not start with wholesale package deletion.** Active architecture and packaging dependencies support keeping the facade, contract, core, fake, native/WASM backends, C shim, parity harness, docs, and native packages. Recommend removing the isolated `perf-analysis` scaffold in a small follow-up; confirm that no private benchmark workflow depends on it before deleting its package and TypeScript reference.
2. **Toolchain bootstrap is complete on this machine.** Node 22, pinned pnpm 10.13.1, uv-managed Python 3.11+, frozen workspace dependencies, and CSPICE are available. Both required validation lanes passed with the host SDK workaround and CI guard caveat recorded below.
3. **Track current-main behavior, not issue claims.** The open issue review confirms raw `kplfrm` currently throws in WASM despite existing in contract and Node. Include it in the backend-by-method ledger and decide whether to implement or document the exception.
4. **Keep the eventual support table evidence-based.** Existing automated coverage is macOS and Linux x64 for Node, plus WASM Node tests; there is no Windows or Linux ARM64 native release package. Browser runtime support is a product target, but the visible current CI workflow does not show a browser integration matrix.
5. **Separate code coverage from function/parity coverage.** The local baseline should include the method-by-backend-case ledger. A Vitest line/branch report is supplementary and must not be described as CSPICE API coverage.
6. **Keep setup repeatable on a contributor machine.** The new [development setup guide](./development-setup.md), doctor profiles, and [scripts catalog](../scripts/README.md) document the tool tiers, bootstrap, CSPICE cache/override behavior, and validation commands. The Corepack shim used locally remains in `/private/tmp/tspice-phase1-bin`; Node/pnpm still need to be made available on the user's desired shell `PATH` for persistent convenience.
7. **Keep generated-output hygiene covered.** Ignore rules now cover the parity-generated kernel directory, Python build metadata/bytecode, and staged platform `.node` file. Verify this cleanup stays effective when fixture or packaging workflows change.
