# Type 2 DSK plate geometry

The six kernel-free raw operations belong to `DskApi`. Each mesh contains flat Cartesian vertex triples and flat signed 32-bit plate triples. Vertex numbers start at one, including in JavaScript. Both backends infer the two row counts from complete triples. The Node and WASM adapters take a finite snapshot of every input component and copy numeric outputs, preserving IEEE signs and nonfinite results. The Node buffers fit a signed 32-bit byte count. The existing WASM allocator limits each individual buffer to 256 MiB. Empty tables use valid physical storage and zero logical rows.

| Method                                      | Geometric observation                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `pltar(vertices, plates)`                   | Sum all face areas in square units. Empty connectivity gives zero, and repeated or reversed faces each contribute their own area.                                                                                                                                                                                                                      |
| `pltvol(vertices, plates)`                  | Sum signed tetrahedral volumes in cubic units. Outward winding gives positive enclosed volume for a closed consistently oriented mesh. Reversing all faces reverses the result. CSPICE checks for four vertices and four plates and validates connectivity. Closure and orientation remain caller preconditions for an enclosed-volume interpretation. |
| `pltexp(iverts, delta)`                     | Supply the nine vertex coordinates of one triangle. Each new offset from the centroid is the old offset times `1 + delta`. All nine output entries retain the original row order.                                                                                                                                                                      |
| `pltnp(point, v1, v2, v3)`                  | Return the closest point and its distance. All coordinates are observed through interior, boundary, outside-edge, vertex, segment and point cases. A repeated endpoint at the longest-edge tie follows the pinned segment-selection path.                                                                                                              |
| `pltnrm(v1, v2, v3)`                        | Return an oriented unnormalized normal. Its norm is twice the triangle’s area. Zero components can retain a negative sign.                                                                                                                                                                                                                             |
| `dskrb2(vertices, plates, corsys, corpar?)` | Return both third-coordinate bounds in the units of the vertices. Code 1 returns radius, 3 returns z, and 4 returns planetodetic altitude. Code 2 and other unsupported codes signal `SPICE(NOTSUPPORTED)`.                                                                                                                                            |

## Coordinate bounds and numerical limits

For latitudinal coordinates the minimum is the distance from the origin to a plate, and the maximum is the largest radius of any vertex. For rectangular coordinates both bounds visit every vertex and the routine ignores connectivity. The radius and altitude implementations dereference every plate ID, so the shared shim checks each referenced index before dispatch in these two systems. `pltar_c` and `pltvol_c` validate their own indices and preserve the toolkit’s `INDEXOUTOFRANGE` and count-error diagnostics.

For planetodetic coordinates provide at least the equatorial radius and flattening, in that order. Additional descriptor parameters are ignored by N0067. Maximum altitude includes unreferenced vertices. The lower bound subtracts each plate's greatest centroid-to-vertex distance from its centroid altitude, then takes the least of these values. NAIF requires convexity of the surface at this lower altitude for the bound to apply. With an empty plate set the lower bound retains the toolkit’s initial `DPMAX`. Fully empty rectangular and planetodetic meshes retain both signed extrema. An empty latitudinal mesh has upper bound zero.

N0067’s `RECGEO` calls `NEARPT`, then uses its private normal in `RECLAT`. A failure in `NEARPT` leaves that normal uninitialized. The shared shim first checks the same linked `NEARPT` component for each vertex and plate centroid using initialized storage and the original public trace. The successful path still calls `dskrb2_c` for both bounds. Nonpositive equatorial radius and flattening at least one reach the original early `VALUEOUTOFRANGE` checks on a nonempty vertex table. A derived polar radius that exceeds the floating-point range is rejected before conversion. An extreme scaled point produces the actual nested `INPUTSTOOLARGE`, including the caller’s trace, and subsequent operations continue in the same client. ## Verification

The 45 registered, project-authored workflows contain 98 calls and 12 expected toolkit errors. The independent oracle invokes the locked SpiceyPy 6.0.3 wrappers for nonempty inputs. For empty rectangular tables a separately typed binding to the same locked library passes the logical dimensions and valid sentinel storage. The planetodetic oracle checks the nested error through the linked SPICELIB symbol with its own declarations and compares successful bounds using the public wrapper. Each supplementary test disposes its own client.

The public tests derive the area and signed volume of an asymmetric tetrahedron, compare very small and large results after rescaling, verify centroid and area after expansion, check a slanted-edge nearest point and distance, and retain both signs of zero and complete nonfinite vector outputs in tagged live comparisons. Native boundary tests check snapshotting, result shape, numeric domains and recovery. WASM tests inject failure at every allocation, check the exact successful buffer sizes, reuse the heap after errors and verify the returned data remains owned. The initial output-ownership assertion for `pltnrm` assumed positive zero in the second normal component. It now compares the saved computed value before and after mutating the returned array. The independent signed-zero tests compare the actual value bit sign.

Both compiled backends passed all 90 registered comparisons, eight supplementary public/oracle tests, 14 native tests and 35 WASM tests. A real Chrome worker exercised all six operations and recovered after the unsupported-coordinate error. Full source-bound local and canonical CI executions are recorded separately.
