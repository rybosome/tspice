# Event kernel metadata and query-file ownership

C10 exposes `ekccnt`, `ekcii`, `eklef`, `eknelt`, `ekpsel`, `ekssum` and `ekuef` through the public raw facade. The Node addon holds the process CSPICE mutex. WASM calls the same shared shim in its own toolkit instance. The checked-in synthetic EK fixtures contain repeated logical table names, multiple physical segments, variable and fixed arrays, nulls and an indexed integer key. The generators and SHA-256 digests are recorded with the original fixture provenance. ## Physical files, query registrations and results

A reader created with `ekopr` can inspect segments without registering tables. `ekssum` returns the actual table name, row/column counts and a new array for every column name and its six attributes. CSPICE data type codes are zero-based. Column size and character length retain the stored values, including −1. Every field is compared for all seven columns of AUDIT_QUERY. The three physical segments of audit-tables-one contain two logical tables, with row counts 2, 1 and 1. [Segment summary](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekssum_c.html) [Loaded column descriptors](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekcii_c.html)

N0067 EKQMGR keeps up to twenty direct query files. Loading a file twice balances the second DAS open and returns the existing registration. One direct unload removes it. A separate ordinary reader survives. KEEPER only unloads its own registrations on KCLEAR, so a direct-only registration survives clearing. When KEEPER removes an overlapping registration, the old public load token can still be released; it cannot unload a new generation of the same DAS handle. The addon tracks generations under the process-wide lock, and each client owns its local tokens. Client disposal releases its remaining tokens before clearing KEEPER. [Loading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/eklef_c.html) [Unloading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekuef_c.html)

The SELECT parser returns every resolved table and column, inclusive zero-based byte offsets, the N0067 type/class codes and the count of projections. It retains repeated items in order, accepts an alias and returns a query-language diagnostic for an unavailable column or an unsupported expression. An empty input instead signals EMPTYSTRING. Fixed 65-byte table and 33-byte column slots preserve complete names throughout the toolkit's intermediate lookups. For `SELECT KEY,CV, DV FROM AUDIT_QUERY` the spans are 7–9, 11–12 and 15–16, and the types are 2, 0 and 1. `ekpsel` does not replace an existing `ekfind` result. [SELECT fields](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekpsel_c.html)

For the ordered CV and DF result, the three variable extents are 1, 1 and 2. All three fixed extents are 2, including the null entry. EKNELT's cached row vectors belong to a completed query. A subsequent successful query establishes a fresh row extent. A file membership change or interrupted query requires a new EKFIND before dereferencing a potentially stale result row. Existing C-level errors for no loaded files and negative indices still use the linked toolkit. Finish active fast writes before running the metadata operations. [Result extents](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/eknelt_c.html)

## Independent observations

In pinned N0067 `ekcii_c.c`, the outer C adapter converts its local descriptor after `ekcii_` returns even when the table or index is invalid. `eknelt_c.c` returns a private, potentially unwritten integer following an error. Both bindings use initialized storage and the original SPICELIB calls with canonical outer check-in/check-out. EKCII's early C width error remains a direct C call. On every successful independent call, the locked oracle also compares the complete result to the high-level SpiceyPy wrapper. Mutation tests for the ledger remove the actual linked scientific symbol independently of the C-width check.

SpiceyPy 6.0.3 declares the cnames extents in its SpiceEKSegSum ctypes layout in reverse order. The allocated field still contains all 3,300 bytes. The oracle reads the original C result from its ctypes field offset with the documented 33-byte row stride and compares all six attributes for each returned column. The first browser expected-value comparison independently exposed the same stride mismatch; correcting the independent expected-name extraction matched all seven physical names. [Locked oracle](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/ek_metadata_oracle.py)
