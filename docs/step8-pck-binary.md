# Binary PCK orientation files

The seven raw frame methods use caller-owned file handles, integer sets and windows. `pckfrm` returns PCK frame **class IDs** by inserting them into a supplied set. For the synthetic terrestrial orientation the class ID is 3000, the frame code is 13000 (ITRF93), and the Earth body ID is 399. `pckcov` adds closed intervals to an existing window. Looking up either 399 or 13000 in this fixture correctly adds no intervals. [PCKFRM](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pckfrm_c.html) [PCKCOV](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pckcov_c.html)

## Type 2 records

`pckw02` stores the three Euler series in phi, delta, W order. Each record starts with a midpoint and radius in TDB seconds past J2000. Increasing Chebyshev orders for each angle are contiguous. CSPICE evaluates each polynomial and its derivative; its state rotation uses W, delta, phi and their corresponding derivatives in a 3-1-3 axis sequence. Descriptor endpoints can trim the permitted interval. At a shared record boundary the reader selects the later record, clipping to the last record at the final endpoint. This matters when successive synthetic polynomials are discontinuous. [PCK required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/pck.html) [PCKW02](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pckw02_c.html)

The raw writer copies the coefficient array once and validates each value before crossing the backend boundary. With degree `d` the reader needs `1 + 2 + 3*(d+1)` double slots, including the separately returned record size. Pinned N0067's PCKMAT and PCKEUL allocate 130 slots, admitting degrees 0 through 41. The shared shim checks the transfer size, finite input values, positive representable record radii for accepted records, finite coverage and index arithmetic, and remaining DAF address space. The writer consumes at most 256 MiB of coefficient data per call. Unsupported dimensions are rejected before dispatch. Nonpositive record count with an empty input, nonpositive interval, invalid inertial reference and invalid descriptor epochs reach the real toolkit errors. External binary kernels supplied for orientation evaluation must be valid PCKs. The loader rejects DAFs identified as another kernel type. ## File lifetime and errors

`pckopn` creates a new file. An empty writer's `pckcls` reports NOSEGMENTSFOUND and preserves the open writer, so a caller can add a segment and retry. A portable VirtualOutput can be read or reopened using the same object after close. Node's physical output namespace is backend-local. A string path uses Node's filesystem or WASM's virtual kernel namespace. The low-level `pcklof` registers the physical file in the process's PCK search table, and does not add an entry to KEEPER. Loading an existing file again promotes it and returns the same owner-local load token. One `pckuof` removes the search-table entry. Distinct writer/load token kinds, physical-load generations and the native CSPICE mutex protect against invalid closes and stale aliases after a direct unload/reload. Users who also manage the same physical file through FURNSH, UNLOAD or KCLEAR must coordinate those process-global registrations. [PCKOPN](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pckopn_c.html) [PCKCLS](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pckcls_c.html) [PCKLOF](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pcklof_c.html) [PCKUOF](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pckuof_c.html)

PCKCOV uses B03's validated live window kind and checks normalized endpoints and bounds. After WINDOWEXCESS the failed canonical wrapper can leave the C descriptor cardinality unchanged while its Fortran control describes an already written interval. PCKFRM has the analogous SETEXCESS behavior. Use `scard(0, destination)` or release the destination before retrying a failed scan. On these two capacity failures the N0067 file scan's DAFCLS returns early because the error flag is still set. The shim captures and resets the error before balancing the retained reader link. An independently held PCK load remains usable during both operations. Data corruption or arbitrary filesystem errors can have different post-error effects. ## Independent observations

Each backend reads the checked-in binary written by locked SpiceyPy 6.0.3. Each also writes a fresh physical PCK for a separate SpiceyPy process to inspect with DAFGS, DAFUS and DAFGDA. That process reads the full descriptor, name, all record midpoints, radii, coefficients, and trailer, then independently calculates a 3×3 rotation and 6×6 state transform. Registered workflows cover multiple frames, priority changes, gaps, inclusive endpoints, degree 41, restored lower-priority data, exact index sets and all scientific error cases. The compiled Chrome inline worker checks all seven methods with a virtual output, empty-close recovery, the written class and coverage, full matrix and state values at two epochs, and unload. Adapter tests exercise every WASM allocation position and independent native owners sharing an underlying DAF reader.
