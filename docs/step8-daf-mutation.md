# DAF comment areas and summary replacement

C03 adds four methods to the existing DAF handle API. Each write targets a live claim acquired with `dafopw`. Each workflow creates its own writable SPK, closes it, and opens the resulting file through the DAF API. Public tests also use private copies of the project-authored two-segment SPK. ## Writing comments and descriptors

`dafac(handle, lines)` appends printable ASCII rows. The toolkit drops trailing ASCII spaces, retains leading and internal spaces, and preserves empty lines. All-blank and empty strings have identical Fortran representations. A nonempty batch of blank rows uses at least one physical space per row during conversion. The zero-row case reaches the original toolkit, which reported `INVALIDARGUMENT` on the tested native, WASM and SpiceyPy libraries. The pinned C string mapper may report an allocation failure first on a platform where `malloc(0)` returns null. [DAFAC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dafac_c.html)

`dafdc(handle)` deletes the entire comment area, including reserved comment records. The two mutators can relocate the file's summary and data records. Start a fresh array search after a relocation to get current data addresses. A read-only handle yields the original `DAFINVALIDACCESS` error even during an active extraction. Finish an active extraction on a writable handle before changing its comment area. N0067 keeps the old record, position and character count while that extraction is live. [DAFDC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dafdc_c.html)

`dafrs(handle, summary)` selects the handle's existing search, checks its ND/NI format and supplies aligned native-order summary words to DAFRS. The input is a `Uint8Array` of exactly `8*(ND+ceil(NI/2))` bytes. CSPICE accepts new double and integer components and keeps the current array's two integer addresses. The file name, array name and data remain accessible after close and reopen. Preconditions include a writable native-format DAF and a currently selected array. [DAFRS](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dafrs_c.html)

## Reading comment pages

`dafec(handle, bufsiz, buffln=1024)` returns the number of defined rows, the rows themselves and the completion flag as `{n,lines,done}`. Width includes the terminator. A full page can finish extraction. Reading after completion starts again at row one. The returned strings and array are independent of later heap allocations and calls. [DAFEC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dafec_c.html)

N0067's public adapter copies a private logical output even on early errors. The shared adapter uses its linked SPICELIB `dafec_` operation with initialized outputs, the same outer error-trace frame, the original width check and the original `F2C_ConvertTrStrArr` conversion on success. A failed short-width read that crosses a physical record can replace the upstream shared record cache before its saved cursor advances. The adapter checks the upcoming line widths using independent reads of the 1,000-byte comment payload in each 1,024-byte file record. It reports the same `COMMENTTOOLONG` short message, row-relative long message and trace via the actual SPICE error subsystem. The scanner supplies no public comment text. Width/count errors use their original callable paths. [Shared implementation](../packages/backend-shim-c/src/domains/file_io.c) [Locked independent oracle](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/daf_mutation_oracle.py)

Raw DAF links to the same file share the toolkit's page position. The shared shim counts these links, including those opened by independent native clients under the process mutex. Closing the final local DAF link completes an active extraction through the original cursor so N0067 releases its internal 5,000-entry reader table. Earlier alias closes preserve the current position. Callers close every raw DAF handle explicitly. The in-process facade’s client disposal performs best-effort kernel cleanup, so an open DAF link survives that disposal. Finalization of the last explicit link measures actual lines and drains at most 64 rows per call with bounded temporary storage. The rectangular input/output limit is 256 MiB. Comment-area arithmetic and file seeks must fit the pinned toolkit's signed counters and the platform C long. [Public contract](../packages/backend-contract/src/domains/file-io.ts)

## Measurements

The 46 registered workflows contain 581 steps and 103 calls to the new methods. Across Node and WASM, all 92 comparisons with the locked SpiceyPy library passed. Sixteen workflows require genuine toolkit errors. Initial checks exposed a missing Python filename wrapper and a missing fixture-staging step on error workflows. The oracle now records actual open paths, and these workflows open independent read-only scratch files and assert the expected status fragment. [Registered cases](../packages/py-parity-checking/src/cases/file-io)

All seven public tests, four native tests and 15 WASM tests passed. The public writers created separate SPKs. Independent locked-library readers checked every comment, the two nonintegral summary doubles, the signed descriptor fields, the retained addresses and every original segment data word. Each backend also completed 5,001 partial-read, close and reopen cycles. The real Chrome inline worker wrote a segment, changed its comments and summary, reopened it, retried a short-width failure and restarted from the first row after EOF.
