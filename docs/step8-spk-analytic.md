# Analytic SPK writers

The ephemeris contract exposes `spkw05`, `spkw10`, `spkw15` and `spkw17` on both real backends. Each appends a segment to a live SPK writer owned by the caller. The common arguments are handle, target, center, frame, start and end TDB seconds, and segment identifier. The adapters capture finite numeric arguments once in an owned buffer. The shared C shim validates the physical dimensions before passing pointers to the four N0067 writers. A single packed allocation is bounded at 256 MiB.

## Open writers and boundary conditions

SPKW10 calls SGBWFS before it submits the reference epochs to SGWFPK. The isolated locked-library test submits two equal reference epochs. The second packet produces `SPICE(UNORDEREDREFS)`. The next valid attempt encounters `SPICE(CALLEDOUTOFORDER)` because the generic segment is still open. Finalizing that partial segment with the linked SGWES entry leaves one target on disk. tspice checks reference order before creating a segment, so callers can retry on the same writer. Passing zero element sets produces a real 25-word generic segment. Its descriptor and coverage can be inspected. State evaluation requires at least one element set.

SPKW05 accepts equal descriptor endpoints. The other three share SPKPDS's strictly increasing descriptor bounds. SPKW17 accepts eccentricity exactly 0.9. Reading that segment's state raises `SPICE(ECCOUTOFBOUNDS)` in KEPLEQ. Separate cases cover successful storage at 0.9, its evaluation diagnostic, and successful evaluation at 0.8999. SPKW15 retains fractional J2 flags. The raw API requires the truncated flag to fit a signed 32-bit integer so SPKE15 can evaluate it.

## Physical and numerical verification

The independent Python writer and each tspice backend exchange five file segments, including one empty type 10 segment. The reader checks full DAF word arrays, descriptor addresses, identifiers and all six Cartesian components at five epochs. Four generated nutation terms have an absolute comparison at 17 decimal places. All remaining stored words are compared exactly. The circular type 5 and 17 results also agree with the analytic position and velocity at those epochs. The type 10 read uses the repository's NAIF0012 leap-seconds fixture. All SPKs are project-authored temporary files. [Independent reader and writer](../packages/py-parity-checking/test/_helpers/spk_analytic_oracle.py) [Public tests](../packages/py-parity-checking/test/spk-analytic-files.test.ts)

A one-second grid of 101 circular type 5 states exposed a velocity difference of about 1.98 × 10⁻¹² km/s between the macOS locked library and both application builds at ET 47.5. The derivative of the blending weight multiplies the difference between two independently propagated positions. The focused test retains the original dense grid, checks the physical hundredth-epoch directory and compares all components against both independent CSPICE and the circular solution with bounds of 2 × 10⁻¹⁰ km and 10⁻¹¹ km/s. The registered directory workflow also exercises a 60-second grid under the existing comparator.

The compiled Node and WASM backends passed 136 registered comparisons over 68 workflows, 442 steps and 115 target calls. The 44 expected toolkit failures comprise 43 writer errors and one downstream evaluation error. Focused tests also cover reciprocal files, same-client replays, direct native buffer lengths, all four WASM allocation failure points, token ownership and retry. A real headless Chrome worker wrote all four segment types and recovered from `BADSEMIAXIS`. Its 24 Cartesian components at ET 1 agreed with the independent library. Required full execution evidence and CI are recorded separately in the batch audit.
