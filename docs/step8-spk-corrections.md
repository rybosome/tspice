# SPK corrections and signal light time

E08 exposes eight N0067 routines in the existing raw ephemeris domain. Body identifiers are signed CSPICE integers. Epochs are TDB seconds past J2000. SPK positions, velocities, light times and light-time derivatives use km, km/s, seconds and seconds per second. These state routines accept inertial frames. The caller supplies the observer state and acceleration in that same frame when the signature requests them.

| Method                                                                     | Returned observations                                                                                                                                                                        |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `spkacs(target, et, ref, abcorr, observer)`                                | Six-component corrected relative state, one-way `lt`, and its derivative `dlt`. Stellar correction obtains the observer acceleration from barycentric velocities at ET ± 1 second.           |
| `spkapo(target, et, ref, observerState, abcorr)`                           | Three-component apparent `pos` and one-way `lt`.                                                                                                                                             |
| `spkapp(target, et, ref, observerState, abcorr)`                           | Legacy apparent `state` and `lt`. Its velocity is the target velocity at the selected epoch minus observer velocity. The stellar correction changes only position.                           |
| `spkaps(target, et, ref, abcorr, observerState, observerAcceleration)`     | Corrected `state`, `lt`, and `dlt`. The three acceleration components in km/s² contribute to the change of the stellar position correction with time.                                        |
| `spkltc(target, et, ref, abcorr, observerState)`                           | Light-time-corrected `state`, `lt`, and `dlt`. A valid stellar attribute leaves the Newtonian result unchanged. Coincident positions give zero light time and derivative.                    |
| `stelab(position, observerVelocity)`, `stlabx(position, observerVelocity)` | Three-component position with stellar rotation for reception or transmission. STLABX uses negated observer velocity. Zero velocity and exact collinear geometry preserve the input position. |
| `ltime(etobs, observer, dir, target)`                                      | Target event epoch `ettarg` and positive elapsed signal time `elapsd`, or zero for coincident events. `->` transmits at the observer and `<-` receives at the observer.                      |

N0067 saves five raw characters of the previous correction option. Its parser accepts embedded and leading blanks. A call using `LT   +S` can therefore leave the saved key for `LT` with stellar attributes. Both builds stage the 35 SPICELIB sources that own this cache. After each successful parse and copy they use the toolkit’s blank-padded `S_CMP` comparison to mark the key reusable only when all significant bytes fit. The next call after a truncated key goes through the original parser, including when it comes from a different public method. Trailing ASCII blanks remain equivalent. The one-time frame and counter initializers retain their original behavior. [Shared build correction](../scripts/stage-aberration-cache.mjs)

The independent pinned wheel uses its original library. The sidecar supplies recognized canonical spellings for mixed-option comparisons. A separate test obtains independent ordinary `LT` and `LT+S` states and derivatives, then interleaves inherited `spkezr` with new `spkacs` calls on both backends. After six leading blanks followed by a valid correction, a subsequent blank option raises `SPICE(INVALIDOPTION)` with the same trace as a fresh locked-library call.

The six kernel-dependent queries bypass the optional transport result cache by default. Loading an overlapping higher-priority segment immediately changes the state, position or event epoch even with identical call arguments. Unloading that file restores the earlier result. Each backend snapshots finite input tuples once, owns its returned vectors, and preserves IEEE scientific output. The two pure stellar transformations retain normal optional caching semantics.

## Canonical execution and error handling

All eight success paths call their named CSPICE entry points. The shared shim checks four intermediate operations before errors can propagate through private N0067 storage. SPKACS checks the observer velocity stencil. SPKAPS checks SPKLTC and the stellar correction's cosine divisor. The legacy SPKAPP checks its own nonstellar light-time solution and the actual STELAB or STLABX calculation. LTIME checks the initial observer and target barycentric states before its first distance calculation. The guards use the same linked SPICELIB components and run under the same backend serialization as the final call. They return the original primary error and caller trace. The ordinary C entry point handles empty strings, unknown frames and the remaining defined branches.

SpiceyPy 6.0.3 declares SPKAPS acceleration as a six-word ctypes array. The N0067 C signature requires three doubles. A private binding in the independent sidecar passes exactly three and checks CSPICE status before using output. A separate safe comparison passes a padded array to the pinned public wrapper and confirms the complete result. The independent guard calls for the four affected error paths use their own declarations and initialized storage. Scalar response fields and every returned vector component are compared.

N0067's STELAB computes a squared norm after scaling by the rounded reciprocal of light speed. For the tested collinear axial vector with nominal speed 299792.458 km/s, the computed squared norm stays just below the diagnostic threshold. The next larger representable axial speed and the tested superluminal three-axis vector produce VALUEOUTOFRANGE. Realistic observer velocities are subluminal. With finite maximal coordinates, geometric SPK range can overflow to infinity and its derivative can be NaN. The supplemental check compares every state and scalar with a tagged live oracle and a finite control.
