# EK scratch files and record edits

C08 exposes five N0067 routines in the existing raw EK domain. Each calls its same-named C routine through the serialized shared shim. A segment and a record each use a zero-based ordinal. Opaque handles are owned by the backend that opened the file. [Typed contract](../packages/backend-contract/src/domains/ek.ts) [EK required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/ek.html)

| Method                          | Observable result                                                                                                                                         |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ekops()`                       | Opens an unnamed scratch EK writer. Explicit `ekcls` closes and releases it. Two simultaneous scratch files have independent segment counts.              |
| `ekbseg(h,tabnam,cnames,decls)` | Creates a segment and returns its zero-based number. Every name has a paired declaration. Distinct physical segments may describe the same logical table. |
| `ekappr(h,segno)`               | Appends an empty record and returns its zero-based number in that segment.                                                                                |
| `ekinsr(h,segno,recno)`         | Inserts before the given ordinal, shifting later records up. Inserting at the current row count appends.                                                  |
| `ekdelr(h,segno,recno)`         | Deletes a record, including its column entry and index links. Later records shift down.                                                                   |

The schema adapter snapshots each array entry once, encodes text as UTF-8 and packs names and declarations with independent NUL-terminated strides. It accepts one through 100 paired columns, matching the public EK column limit. A schema buffer may use up to 256 MiB. Embedded NUL and isolated UTF-16 surrogates cannot represent a single faithful C string. The toolkit evaluates the table identifier, column identifiers, declaration grammar, data types, index and null flags. N0067's missing-DATATYPE diagnostic is spelled `BADCOLUMDECL`. Other declaration errors can produce `BADCOLUMNDECL`. The tests include the 100-column boundary, independent schema groups and real non-ASCII identifier rejection.

New rows have uninitialized column entries. Their data must be assigned using the entry writers before querying. This batch exposes the row operations; the existing fast-write API populates whole columns. A verified alternative for an unfinished row is to delete it. EKINSR initializes each entry pointer to −1, and each of the six ordinary column-class delete implementations recognizes that value. The registered cases delete newly empty rows before querying. They also edit a fully populated and finalized file and query its surviving rows. An I/O failure during a mutation can leave its file incomplete. [Append](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekappr_c.html) [Insert](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekinsr_c.html) [Delete](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekdelr_c.html)

The class codes from an actual segment summary distinguish editable record classes 1 through 6 from fixed-count classes 7 through 9. EKBSEG may create either segment type. The shared shim restricts these row mutations to editable segments, including when opening an existing file. A completed ordinary fast-written segment may subsequently be edited. An active fast writer is process-global in native CSPICE, and none of these five operations may interrupt it. The guard starts after successful EKIFLD and ends after successful matching EKFFLD or closing its writer. Failed finish calls retain the guard. File access and out-of-range ordinals flow to the actual toolkit diagnostic. A signed 32-bit maximum ordinal cannot pass the pinned C wrapper's one-based increment. EKAPPR and EKBSEG decrement their output even after some scientific errors, so both transports supply initialized output storage and only consume it after success. [Shared C implementation](../packages/backend-shim-c/src/domains/ek.c)

## Independent evidence

All five ordinary wrappers exist in the locked SpiceyPy 6.0.3 library. Its EKBSEG wrapper computes strides using Python character counts. For multibyte and empty rows the oracle binds the exact canonical C symbol with independently packed byte rows. Its EKSSUM wrapper declares the 3,300-byte names field with transposed dimensions. The public cross-file test reads that field at its actual offset using the N0067 `cnames[100][33]` layout and checks every defined attribute in a three-column mixed schema. [Independent toolkit adapter](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/ek_record_oracle.py)

The 38 workflows contain 227 steps, 147 calls to the new routines and 23 expected terminal errors. All 76 registered Node/WASM comparisons passed. Four supplementary tests cover native/WASM persisted edits in both directions and scratch writer state. Each independent writer starts from its own copy of the existing project-authored EK and closes its file before a different reader inspects it. Query results distinguish the surviving rows and verify the removed indexed key. Real Chrome exercised the public inline worker on the staged binary. It created a scratch writer and schema, appended, inserted and deleted rows, checked zero-based ordering and INVALIDINDEX, observed failed=false, retried and closed. Three native and 17 WASM boundary checks include all allocation positions and publication failure cleanup.
