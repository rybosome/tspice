# DLA linked segments

A DLA stores its segment list as eight-integer descriptors in the DAS integer address space. Each segment can contain independent streams of arbitrary bytes, double-precision numbers and signed integers. No kernels are required to construct or walk a generic file. The public methods accept DAS or DLA claims belonging to the current backend. [NAIF DLA required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/dla.html)

| Method                  | Result and observable effect                                                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dlabns(handle)`        | Append a descriptor to a writable DLA, update the file's list pointers and link the previous segment immediately.                                                        |
| `dlaens(handle)`        | Write the actual integer, double and character component sizes into the current last descriptor. Leave the file open for more writes.                                    |
| `dlabbs(handle)`        | Return the last descriptor in an owned `{found:true, descr}` result. An empty file returns `{found:false}`.                                                              |
| `dlafps(handle, descr)` | Return the descriptor reached by the supplied backward pointer. The first segment has no predecessor. The caller may start from any valid descriptor from the same file. |

The first three integers hold version 1,000,000, the first descriptor address and the last descriptor address. The empty list uses −1 for both addresses. A descriptor contains `bwdptr`, `fwdptr`, `ibase`, `isize`, `dbase`, `dsize`, `cbase` and `csize`. Links point to the first integer of a descriptor. The base for each type is the address immediately preceding its data. A completed component's inclusive address range is therefore `base + 1` through `base + size`. A zero size means the component is empty. [DLABBS](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dlabbs_c.html) [DLAFPS](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dlafps_c.html)

Begin a segment, append through `dasadc`, `dasadd` and `dasadi` as needed, then call `dlaens`. Each size remains −1 until the descriptor is finalized. An earlier copy of a descriptor retains its observed values when a later append updates a link. Repeating `dlaens` recomputes the last descriptor's sizes from current logical addresses. Completing an unfinished segment after reopening its writer works because the bases and list endpoint live in the file. [DLABNS](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dlabns_c.html) [DLAENS](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dlaens_c.html)

## Checked scientific entry points

Both backends call all four original N0067 C routines for supported writes, successful searches and ordinary misses. Each WASM call owns its temporary storage. A native process holds the CSPICE mutex across checks and the final call. A descriptor argument is copied once, including provisional size words, before the adapter resolves the handle. The same representation works in existing forward searches. Results omit the descriptor on a miss.

The pinned readers assume their descriptor's eight logical integer addresses are available. The pinned writer routines also use intermediate values after some early file-read failures. The shared shim reads the required controls and complete descriptor with initialized storage before entering the public C routine, checks signed address arithmetic and validates the bases needed for size computation. An out-of-range endpoint is sent to the original DAS reader as a singleton so it produces its own diagnostic before any padding could be read. A null backward link bypasses file reads. The adapter preserves the original writer access check and nested traceback. On a populated read-only file, begin reports `DASINVALIDACCESS` through `DASSIH`, while end reports it through `DASUDI → DASURI → DASSIH`. [Shared implementation](../packages/backend-shim-c/src/domains/file_io.c)

The three DLA control integers and each eight-integer descriptor are appended internally via DASADI. After an append creates a new partial physical integer record, the adapter applies the inherited C05 padding policy to its unused suffix. DLAOPN finishes this step before publishing its writer handle. A failure closes the newly opened native claim. This adds no file flush. The two compiled backends retain all 11 defined words and 980 zero padding bytes in an ordinary one-segment file; when a new descriptor follows exactly 256 used integer words, a fresh reader finds the next eight words and 992 zero bytes. [Typed DAS data and record padding](step8-das-data.md)

## Independent observations

SpiceyPy 6.0.3 has all four wrappers. The sidecar calls the independently linked wrappers with found checking disabled just around traversal, preserving the actual boolean. It guards the same preconditions on its own files. For an invalid descriptor extent it calls the failing SPICELIB DASRDI suboperation in the original outer trace with initialized outputs. The first registered run exposed one incorrect test expectation. The actual singleton DAS lookup of the empty list's −1 last address reports `DASNOSUCHADDRESS` with a valid range of 1 through 3. Both backends now compare that observed diagnosis and recover on a subsequent real segment. [Independent reference](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/dla_segment_oracle.py)

The public tests write three unequal generic DLA segments using each backend, then reopen the physical file with the locked library. In the reverse direction each backend reads another DLA independently written by SpiceyPy. Both forward and backward walks compare all eight descriptor words and all integer, double and character values. The payload contains NUL and high bytes; an empty middle segment has distinct links and zero component sizes. The export test uses DASONW's supported VirtualOutput with the exact three DLA control integers. Other workflows and backend tests also use DLAOPN directly. WASM stages the independent generic file through the existing byte-backed file input, observes KEEPER's unsupported kernel type and opens the file with DASOPR. The tests create and dispose their own files, handles and clients. Four-segment read-only cases also use the repository's synthetic tetrahedral DSK.
