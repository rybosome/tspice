# E11 ellipse geometry

The seven geometry methods use a `SpiceEllipse` containing `center`, `semiMajor` and `semiMinor`. All three fields hold independently owned three-component vectors. Inputs also accept readonly tuples. The backend ABI transfers exactly nine doubles in that field order and copies each named member of the CSPICE structure. Projecting or intersecting an ellipse uses the four-component plane representation from E10. [Plane geometry](step8-plane-geometry.md)

## Construction, extraction and orientation

The generating vectors describe `center + cos(t) vec1 + sin(t) vec2`. They can be skew, linearly dependent or zero. CSPICE computes orthogonal semi-axes for the resulting image. Both axis signs and the orientation of a circle's equal-length axes can be geometrically nonunique. The adapters expose CSPICE's selection directly. The extraction routine copies the stored components in their original order, preserving orientation and signed zeros. Public tests use skew generators and verify orthogonality, the sum of squared semi-axis lengths and normalized components at an input scale of 2⁻⁴⁰⁰. [CGV2EL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/cgv2el_c.html) [EL2CGV](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/el2cgv_c.html) [SAELGV](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/saelgv_c.html)

Orthogonal projection acts on the center and both directions. A proper ellipse viewed edge-on can produce a segment. Projecting a segment along its only direction can produce a point. NPELPT requires both axes to have nonzero length and works in the coordinate units of the point and ellipse. A point inside the ellipse can have more than one closest boundary point. Its caller must keep scaling and translation within the range of the underlying computation. [PJELPL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/pjelpl_c.html) [NPELPT](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/npelpt_c.html)

## Intersections and conditional outputs

A triaxial ellipsoid intersected exactly at a tangent plane can yield `{found:true, ellipse}` with both semi-axes zero. A miss returns `{found:false}`. Near tangency the numeric classification depends on roundoff. For ellipse/plane intersections, `nxpts=-1` denotes a contained non-point ellipse and `nxpts=0` denotes no intersection. Both omit the undefined points. A point ellipse lying in its plane returns count one. Tangent or segment intersections with count one still return both computed point vectors individually. For count two, the original CSPICE point order is preserved. [INEDPL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/inedpl_c.html) [INELPL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/inelpl_c.html)

The pinned N0067 C implementation of INEDPL continues using its private distorted plane after the plane constructor signals a failure. The shared shim checks that same intermediate with initialized storage and the genuine outer traceback before entering the direct INEDPL call. Nonpositive radii still reach the canonical early error, and a plane farther away than the maximum radius still reaches the canonical miss. Both compiled backends preserve the scoped distortion error and subsequent normal calls. The independent diagnostic observation uses only the defined component operations. For NPELPT, the fixed frame-axis indices are 1 and 2. The translated TWOVEC routine defines all three rows before diagnosing dependent vectors at those indices. The shim checks incoming error state, initializes its private nearest-point and distance outputs, and checks final SPICE status before publishing either. ## Observed checks

The 39 registered workflows contain 93 canonical calls. Eight terminate in expected scientific errors. Three INEDPL cases exercise invalid radii, three INELPL cases exercise invalid ellipse axes or plane normals/constants, and two NPELPT cases exercise zero-length semi-axes. Every case uses project-authored numeric data and the corresponding SpiceyPy 6.0.3 wrapper. The independent sidecar reconstructs stored ellipse and plane words without running a second geometry constructor. Public tests additionally verify geometric membership, axis scaling and output ownership. All 78 registered compiled comparisons, four public tests, 19 native tests and 43 WASM tests passed. A real Chrome inline worker exercised all seven operations. The inherited E10 suites also passed their 20 native and 49 WASM tests.
