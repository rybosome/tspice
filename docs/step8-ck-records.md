# CK frame and record access

C13 extends the raw frames API with seven N0067 routines. It builds on the owned DAF handles and native-order packed descriptor bytes from [C01](https://github.com/rybosome/tspice/pull/727) and [C02](https://github.com/rybosome/tspice/pull/738).

## Descriptor and error boundaries

Each record reader checks the open DAF claim, CK file type and two-double/six-integer summary layout. The C shim traverses the physical summary chain and matches all 40 native-order bytes against an actual segment. A byte-identical descriptor describes the same layout in any CK file that really contains it. The lookup preserves active DAF searches and accepts owned copies from earlier cursor positions. Previously captured byte arrays remain caller-owned after closing their file, while the closed handle loses access.

N0067 CKNR03 and CKGR03 convert the final double word to an integer count. CKGR02 copies a local packet immediately after its DAF read. The shim validates actual record bounds, file free address, directory lengths, integral type 3 trailer counts and packet readability where required. A genuine different segment type still reaches CKWRONGDATATYPE, and an invalid signed ordinal on a matching segment reaches CKNONEXISTREC. Deliberately mismatched descriptors are exercised only at the protected tspice boundary. The independent oracle receives descriptions from successfully opened authored files.

CKFROT and CKFXFM initialize matrix storage because their C wrappers transpose the output even on absence. They read only a found result. The pinned ZZSCLK implementation negates the SCLK ID, so these adapters resolve CKMETA before dispatch and reject a loaded-CK lookup whose mapped clock is −2147483648. CKMETA itself can return that exact signed value. Real pool conversion errors retain their CSPICE diagnostic, and subsequent corrected calls succeed. All seven native handlers take the shared CSPICE mutex.
