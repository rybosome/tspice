# Civil time and local solar time

The five methods in the existing raw time API use the linked N0067 implementation in both backends. Their kernel requirements and parameter units differ. Native clients share the CSPICE parser settings in their process. Each WASM module has its own toolkit state. [Contract](../packages/backend-contract/src/domains/time.ts)

| Method                                           | Result and scientific inputs                                                                                                                                                           |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `etcal(et, callen?)`                             | Formal Gregorian calendar with fixed 86400-second days, from ephemeris seconds relative to J2000. No kernel required. The signed capacity includes the terminator and defaults to 181. |
| `utc2et(utcstr)`                                 | TDB seconds from J2000. Uses the current leap-second kernel and legacy UTC parsing. Explicit time zones, AM/PM and alternate time systems produce INVALIDTIMESTRING.                   |
| `tparch(type)`                                   | The native comparison of the supplied string with YES enables strict calendar checks. Other nonempty selectors enable permissive normalization.                                        |
| `tsetyr(year)`                                   | A positive lower bound changes the 100-year interpretation window for abbreviated years. Nonpositive signed integers leave the current setting unchanged.                              |
| `et2lst(et, body, lon, type, timlen?, ampmlen?)` | At ephemeris seconds and longitude in radians, returns `{hr,mn,sc,time,ampm}`. The two output capacities include their terminators and default to 9 and 14.                            |

ETCAL truncates using the requested output capacity and CSPICE's conversion of trailing Fortran blanks. Its finite extreme epochs produce toolkit text beginning with “Epoch before” or “Epoch after”. UTC2ET instead uses the leap-second table. The tests check the two adjacent one-second differences across 2016 December 31, supplementing the registered comparison at large absolute epoch values. [ETCAL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/etcal_c.html) [UTC2ET](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/utc2et_c.html)

The greatest supported TSETYR lower bound is 5,851,355. The expanded century can reach `lower+99` and the existing N0067 TPARSE computes `367*year` as a signed SpiceInt. Each parity workflow observes the entry parser mode and century before changing them, then restores the caller’s values on both exit paths. The native setting survives disposal of an individual client. [TSETYR](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/tsetyr_c.html) [TPARCH](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/tparch_c.html) [Cleanup tests](../packages/py-parity-checking/test/civil-time-public.test.ts)

For UTC2ET, the shim obtains the actual N0067 TPARTV calendar decomposition before checking rounded years, signed Gregorian-day intermediates and JD day conversion. TTRANS uses the live leap-second reference days in signed subtractions. The check includes those references, and preserves ordinary missing-leap-table and invalid-time-string diagnostics. Guard-only tests feed extreme dates and a temporary malformed table to the checked backend and verify recovery. Independent scientific scenarios use defined date/kernel inputs. [Shared implementation](../packages/backend-shim-c/src/domains/time.c) [Guard tests](../packages/backend-node/test/time-additions-domain.test.ts)

ET2LST derives its 24-hour and 12-hour outputs from the apparent body-to-Sun state in the selected body frame, the supplied longitude convention, and the sense of rotation. A Sun planetocentric call returns noon immediately. A planetographic call first converts longitude using PGRREC, including its planetary rotation-data requirements. The N0067 translation proceeds to RECLAT after PGRREC or SPKEZ even when the producer failed. The shim uses those exact prerequisites with initialized local storage under the original two caller frames and checks their statuses before continuing. Body lookup also checks the representability of signed hash operands, including programmatic additions to the kernel pool. The original canonical routine performs the final computation and text formatting. [ET2LST](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/et2lst_c.html) [Oracle](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/civil_time_oracle.py)

The registered suite has 38 workflows, 163 steps and 95 invocations of these methods. Sixteen workflows end in a diagnostic, including one existing TPARSE return-message path. The other steps exercise parser effects or set up kernel state. The geometry scenarios use the existing project-authored fixed frame and ephemerides plus a synthetic rotation rate. The UTC scenarios reuse the repository's unchanged NAIF LSK. Scientific comparisons use locked SpiceyPy 6.0.3. Four public tests cover caller-configured parser restoration and known numerical/text results on both backends. Fourteen Node adapter/native tests and twenty WASM allocation, output and recovery tests passed. Both compiled runtimes passed all 38 registered cases, for 76 comparisons. A real Chrome worker loaded the regenerated WASM and exercised every method, including strict parser recovery, calendar rollover, the UTC offset and both complete local clocks. Full required local and canonical CI execution records are maintained separately by source fingerprint.
