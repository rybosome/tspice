# EK record entries

The nine `EkApi` methods address a column by an owned EK handle, a zero-based segment, a zero-based record and a column name. Use `ekappr` or `ekinsr` to create a row, add each entry, then use the corresponding update method to replace it. Close a named file with `ekcls` before passing it to an independent reader. Complete any active fast write first. [NAIF EK required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/ek.html)

| Columns                   | Add      | Read     | Update   |
| ------------------------- | -------- | -------- | -------- |
| Character                 | `ekacec` | `ekrcec` | `ekucec` |
| Double precision and TIME | `ekaced` | `ekrced` | `ekuced` |
| Signed 32-bit integer     | `ekacei` | `ekrcei` | `ekucei` |

Add and update take `(handle,segno,recno,column,values,isNull)`. Arrays supply their own count. Ordinary scalar classes consume the first element. Array-valued classes require a positive count even for a null, and fixed-size vectors require the declared count. Supply placeholders when writing a null. Double and TIME values are finite numbers, with TIME expressed as ET seconds. Each read returns an owned `{nvals,isNull,values}`. A null returns an empty values array and preserves its actual count, one for variable-size entries and the declared size for fixed-size entries. [EKACED](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekaced_c.html) [EKRCEI](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekrcei_c.html)

Character writers derive a common NUL-terminated row stride from UTF-8 byte lengths. Character reads accept a final `lenout` argument in bytes including NUL, default 1024. N0067 uses `F2C_ConvertStrArr`, which leaves all Fortran trailing blanks intact. A returned non-null row thus contains up to `lenout−1` bytes including its padding. Embedded tabs, leading spaces and a leading BOM are retained. Invalid UTF-8 raises a representation error, including when a scalar truncation splits a sequence. Class 3 scalar reads return initial bytes at shorter widths, as `ZZEKRD03` explicitly permits. Classes 6 and 9 require enough width for the declared character element. All classes retain the C-level two-byte minimum. [EKRCEC](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekrcec_c.html)

## Compiled access and bounds

The six writers invoke their linked canonical C routines for ordinary inputs. The two character writers use the same traced SPICELIB operation with a real one-byte placeholder for a zero-length vector, avoiding the C row packer's two zero-byte allocations. A zero-length scalar input is rejected before calling code that consumes the first element. Individual entry writes use variable-count segments. Readers also support finalized fixed-count classes 7–9 with a valid row. Those classes calculate physical addresses directly, so the adapters check the actual row extent. Add requires a new entry. Numeric scalar classes report `NONEMPTYENTRY` on a repeated add. For the other classes the adapters check the on-disk entry pointer before calling N0067 because these writers can replace a pointer without releasing the original storage. Use update for an existing value. N0067’s populated integer and double scalar update paths skip the non-nullable schema check. The adapter rejects that specific null transition before either its data or index changes. The normal add still reports the toolkit’s BADATTRIBUTE. Updates use the toolkit's own deletion and insertion behavior, including changes to indexes. An error partway through an update can leave an uninitialized entry. Reinitialize it before subsequent queries. [EKUCEI](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ekucei_c.html)

Each C reader unconditionally copies a private logical after the linked reader returns. A failing inner operation may leave that logical unset. EKRCEC also converts output rows after failure. The compiled adapters call `ekrcec_`, `ekrced_` or `ekrcei_` with initialized outputs, reproduce the outer trace and use the linked C string conversion on successful non-null text. The original public C-level empty-column and short-character-width checks remain in use. The shared shim checks segment metadata and record-tree lookups before the translated routines continue with a missing pointer. It measures each array using `ZZEKESIZ` against the same file, then checks the output capacity again at dispatch. Backend-owned buffers are bounded to 256 MiB each. Both transports validate ordinals before converting to one-based signed integers. The Node addon serializes the size lookup and read together, while WASM releases all temporaries across both stages. [Shared shim](../packages/backend-shim-c/src/domains/ek.c)

## Independent execution

The oracle opens its own file in the locked SpiceyPy 6.0.3 library. A fresh named EK receives the same typed operations separately on each side. The in-process Python extent comes from that file’s actual descriptors. Numeric reads cross-check the initialized SPICELIB result against the ordinary public wrapper with the measured room. Character reads also check the full independent C bytes because the Python string converter strips trailing whitespace. Byte-counted C writer bindings handle non-ASCII or all-empty string rows. For doubles the locked `sp.ekuced` function calls `ekaced_c` on line 5460. The original run exposed the resulting `NONEMPTYENTRY` when replacing a populated scalar. The independent oracle now binds the correct `ekuced_c` in that same library. [Independent bindings](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/ek_entry_oracle.py)

The 82 registered cases contain 508 workflow steps, including 175 calls to the new methods and 55 expected terminal toolkit errors. All 164 independent comparisons passed on the compiled Node and WASM routes. The four supplementary tests verify actual file interoperability in both directions, including every component of a 137-element TIME entry, fixed-size integer nulls, byte-padded UTF-8 text, and an index lookup after replacing its key. A literal padding expectation in the first supplemental run counted UTF-16 units. The corrected assertion counts the six UTF-8 bytes in `" café"` inside an eight-byte row. Both independent readers already agreed on the bytes. Three Node tests cover native argument and result ownership. Forty-two actual-heap WASM checks cover every allocation ordinal, successful calls and retry. Real Chrome passed all nine methods through the normal inline worker on the final rebuilt binary, including variable doubles, padded text containing a tab, a two-element null with empty values, and a subsequent valid replacement. A separate non-nullable integer retained its original value 19 after the rejected null update, with the toolkit failure flag clear. The registered fixtures and both persisted files use original synthetic values and independent temporary storage.
