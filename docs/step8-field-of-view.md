# Instrument field of view

The raw geometry API exposes four N0067 routines. Instrument kernels supply the boresight, frame, shape and boundary definition. The existing body-name and UTF-8 handling from the geometry quantities batch also applies to instrument and observer names. [Typed geometry contract](../packages/backend-contract/src/domains/geometry.ts)

| Method                                                       | Result and units                                                                                                                                                              |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getfov(instid, room, shapelen?, framelen?)`                 | Shape, reference frame, boresight, number of boundary vectors and ordered rows. Room counts vectors. Shape and frame widths include a terminating NUL byte and default to 81. |
| `getfvn(inst, room, shapelen?, framelen?)`                   | The same fields for an instrument name or signed numeric string. Both lookups preserve original vector magnitudes.                                                            |
| `fovray(inst, raydir, rframe, abcorr, observer, et)`         | Boolean visibility of a ray in its supplied frame. ET is TDB seconds past J2000. The ray permits NONE, S and XS.                                                              |
| `fovtrg(inst, target, tshape, tframe, abcorr, observer, et)` | Boolean visibility of the target at ET. POINT accepts an empty target frame. ELLIPSOID uses the supplied body-fixed frame, semiaxes and apparent limb.                        |

N0067 reads the shape into the caller's field before interpreting it. A truncated shape can produce a diagnostic even when the untruncated IK is valid. The returned frame follows the actual byte width. A truncated multibyte sequence raises a decoding error on both backends. The implementation checks input capacities as signed SpiceInt values and bounds physical storage using the pinned pool size of 400,000 values and maximum string length of 80 bytes. Counts and vectors are copied only after the compiled call succeeds.

Named lookup preflights an unknown instrument using initialized translation storage and preserves the GETFVN diagnostic. Successful lookups and both visibility operations call their matching public CSPICE routine. The independent oracle binds the byte-sized getfov/getfvn outputs from the library shipped with locked SpiceyPy 6.0.3. Its convenience wrappers decode these text fields differently. [Independent field reader](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/field_of_view_oracle.py)

The four-instrument IK supplies explicit non-unit corner vectors, unequal ellipse axes, an angle-defined rectangle and a polygon in a rotated frame. The authored moving observer crosses the circular field's center boundary at ET ±50 seconds. The ellipsoid remains partially visible beyond those times. Each of 68 workflows compares the complete lookup record or visibility result, or checks the expected toolkit diagnostic. Native and WASM passed all 136 comparisons. Ten public tests check the tangent ratios, center-versus-limb distinction, UTF-8 fields, mutable input access, owned rows and recovery. The compiled addon check covers private entry arguments. Actual WASM tests exercise all acquisitions on success and failure, including the three diagnostic buffers. A real Chrome worker matched independent ordered rows and visibility results on both sides of contact.
