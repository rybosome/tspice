# Diagnostic devices, message selection and traceback lifetime

Three raw error utilities expose the corresponding N0067 C controls. Native calls share the toolkit’s process-global settings and execute under its mutex. Each WASM module has independent settings. The shim establishes RETURN and disables diagnostic printing once, leaving later device and print settings intact across routine calls, reset and kernel clear. The initial device is SCREEN. [NAIF error handling](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/error.html) [Shared implementation](../packages/backend-shim-c/src/errors.c)

| Operation                                                   | Observable effect                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `errdev("GET", capacity = 256)` and `errdev("SET", device)` | Select SCREEN, NULL or a filename. GET returns the toolkit’s stored spelling. Reserved device names are canonicalized.                                                                                                                                             |
| `errprt("GET", capacity = 41)` and `errprt("SET", list)`    | Apply comma-separated items from left to right. NONE clears the selection. SHORT, LONG, EXPLAIN and TRACEBACK add individual items. ALL adds those four and DEFAULT also adds the toolkit’s default explanatory item. GET returns selected items in toolkit order. |
| `trcoff()`                                                  | Disable trace collection permanently in this instance and clear the current stack. Reset, kclear and a new client sharing the native toolkit preserve the disabled state. A new process or WASM module provides an independent trace.                              |

Each signed byte capacity includes the NUL terminator. Both adapters bound the physical buffer by the largest possible result. Capacities below two reach CSPICE’s STRINGTOOSHORT path. Smaller valid capacities truncate the toolkit output. A split UTF-8 scalar raises a representation error. The adapters preserve significant trailing tabs. [Raw API](../packages/backend-contract/src/domains/error.ts)

## Device files

Pass a new, caller-owned filename under an existing directory. Native uses the host filesystem. WASM uses its module filesystem. Merely selecting a pathname does not grant the kit’s virtual-output read permission. N0067 stores at most 255 bytes. Its documented length check examines an already shortened 255-byte field. A long name can therefore select a different physical spelling. SET performs no file creation. WRLINE opens a new file on first output, retains the logical unit and buffers writes. Selecting another device updates its name. A native process exit flushes output. MEMFS inspection while a module is alive can observe only the flushed prefix. The tests compare every byte of the completed native file and of the flushed MEMFS prefix with a separate independent report. [ERRDEV](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/errdev_c.html) [File comparisons](../packages/py-parity-checking/test/error-policy-public.test.ts)

## Print selections and tracing

Selections accumulate across calls. N0067 parses up to ten nine-byte list fields. If a list contains an invalid item, the toolkit signals INVALIDLISTITEM and applies valid selections before and after that item. Printed output and captured structured errors are separate observations. Disposable clients compare complete SCREEN output for SHORT and LONG individually and confirm silence with NONE or NULL. Both optional transport caches perform each call so repeated GETs and mutations observe the changing state. [ERRPRT](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/errprt_c.html)

The 29 registered workflows use a fresh native or WASM child process and a separate Python process. A pending-failure executable exercises actual immediate return on both getters and verifies that TRCOFF still takes effect while failure is pending. The public raw surface normally captures and resets an error before control returns to JavaScript. No cleanup step attempts to re-enable disabled tracing. [TRCOFF](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/trcoff_c.html) [Pending failure](../packages/backend-shim-c/test/error-policy.c)

## Independent reference

SpiceyPy 6.0.3’s `errprt` convenience function calls the device routine. Its string decoder also trims trailing whitespace. The observer binds the actual `errprt_c` and `errdev_c` symbols from the independently loaded locked toolkit, supplies owned storage, checks status and strictly decodes the returned bytes. It invokes the locked `sp.trcoff` wrapper directly. The reference explicitly starts with SCREEN and printing disabled to match the frontend’s initial settings. No kernels are needed. [Independent observer](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/handlers/error.py)

Both a closed-and-reopened native client and a freshly constructed WASM client were exercised in disposable children. The native process retained the chosen NULL device, SHORT mask and disabled tracing. The new WASM module began with SCREEN, an empty mask and an active trace. [Client lifetime checks](../packages/py-parity-checking/test/_helpers/error-device-lifetime.mjs)

An isolated real Chrome inline worker matched the independent locked reference for initial settings, selected device, full and byte-limited mask, INVALIDLISTITEM with post-error mask, the live stack before disabling, and permanent trace disabling across reset and kernel clear.
