# Legacy ellipsoid surface geometry

E14 adds five raw geometry operations. Each shared shim calls its matching CSPICE C entry. The public adapters use owned coordinate buffers and the native handler serializes toolkit calls. Each cached public client observes subsequent changes to ephemerides, radii and frame associations.

| Raw method                                                           | Returned scientific quantities                                                                                                                                                                                                                                                                       |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `illum(target, et, abcorr, observer, spoint)`                        | Solar phase, incidence and emission in radians as `{phase, solar, emissn}`. The surface point is in km in the default target-fixed frame. The observer and Sun positions are corrected at the target center before applying the surface offset.                                                      |
| `srfxpt(method, target, et, abcorr, observer, dref, dvec)`           | A ray hit returns `{found:true, spoint, dist, trgepc, obspos}`. The surface point and target-to-observer position are in the default target-fixed frame, the observer-to-point distance is in km and the intercept epoch is in TDB seconds past J2000. A genuine miss returns `{found:false}` alone. |
| `subpt(method, target, et, abcorr, observer)`                        | `{spoint, alt}` in km. Near point minimizes distance to the ellipsoid and admits negative signed altitude for an interior observer. Intercept follows the radial line and reports the distance to that intercept.                                                                                    |
| `subsol(method, target, et, abcorr, observer)`                       | The target-fixed sub-solar point in km, either nearest to the Sun or along its radial line. For corrected observations the legacy routine computes the target's reception epoch from the observer, then looks up the Sun from the target.                                                            |
| `edterm(trmtyp, source, target, et, fixref, abcorr, observer, npts)` | `{trgepc, obspos, trmpts}` with the center epoch, target-to-observer position and all ordered terminator triples in the explicitly named target-fixed frame. The source is modeled by a sphere with its largest supplied radius.                                                                     |

The first four operations use the frame associated with the target by the kernel pool. EDTERM accepts an explicit target-centered frame. The existing synthetic ellipsoid has radii of 3, 2 and 1 km. A new one-line FK assignment associates its existing fixed frame with synthetic target 100101. The scientific cases also change that association to a rotated frame. All ephemerides, radii and frame definitions are project-authored. [Association fixture](../packages/py-parity-checking/fixtures/kernels/audit-legacy-frame.tf) · [Original geometry generator](../packages/py-parity-checking/fixtures/generate-audit-geometry.py)

NAIF documents the first four interfaces as supported for backward compatibility. Light time in SRFXPT is to the actual intercept. At ET zero a ray from x=20 km toward the ellipsoid hits x=3 km, so reception gives an intercept epoch of −17/c. EDTERM uses −20/c for the target center with the same observer. Both can also calculate transmission. ILLUM retains its legacy target-center light-time handling. The EDTERM output contains exactly the specified number of point triples, including when one or two points are requested. ## Intermediate failures in N0067

The translated ILLUM, SRFXPT, SUBPT and SUBSOL routines can use a local result after a lower-level frame lookup, body lookup, state calculation or geometric operation signals an error. Examples include ILLUM's use of the first state’s light time and SUBPT's negation of its target state after an SPK lookup. SRFXPT sets its found flag false on entry, but a failed position calculation can still leave intermediate data undefined. The native and WASM builds stage the same four pinned translations. At specific call sites a failed toolkit state now returns through the enclosing routine's checkout before a local result is consumed. The original error has already been raised with its trace. Existing success calculations, source constants, order of operations and public C entries are retained. SHA-256 and call-site counts bind the changes to N0067. The four transformed source files are build products. EDTERM uses the unmodified toolkit. [Checked source staging](../scripts/stage-legacy-geometry.mjs) · [Toolkit source manifest](../scripts/cspice.manifest.json)

The shared shim reuses E16's body-name/code table guard before body resolution. It rejects a resolved signed-minimum body code before the toolkit's signed absolute-value hash. Empty public text retains the canonical entry's EMPTYSTRING handling. The caller supplies finite coordinates and ET, well-formed UTF-8-compatible strings and signed 32-bit counts. EDTERM's packed descriptor is four doubles followed by three doubles per point. The 256 MiB limit permits 11,184,809 points. Nonpositive counts use non-null sentinel storage to reach the toolkit's own INVALIDSIZE. Every confirmed row is copied. A miss or error exposes no unspecified output. ## Independent checks

The reference uses the independently installed SpiceyPy 6.0.3 N0067 library. It checks ordinary state and geometry prerequisites with locked toolkit operations before calling an original legacy routine whose intermediate failure would be unsafe. Successful scientific values come from the original high-level wrappers. The SRFXPT comparison explicitly disables the default found exception and observes the true flag. EDTERM's nonpositive count cases use the matching typed public C symbol with bounded non-null storage so that Python’s array allocator does not replace the original scientific error. [Independent reference](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/legacy_surface_oracle.py)

The 74 registered workflows cover 314 steps, 113 target calls and 43 terminal scientific diagnostics. Both compiled backends passed all 148 scientific comparisons. The tests check the triaxial surface equation, nearest-point normal, signed interior altitude, center versus intercept epochs, origin behavior, true ray absence, non-unit directions and correct ordering of both terminations. On the finite-source model, the signed distance from the tangent plane to the source center is −1 km for the umbral boundary and +1 km for the penumbral boundary. Ten public tests cover analytic geometry, independent result storage, post-error recovery and both synchronous and asynchronous cache paths. Two native tests check bounds and single-read inputs. Thirty-four WASM tests cover every adapter allocation-failure position.

A real Chrome inline worker compared all five operations against the independent library. It transferred complete nine-point umbral and penumbral rings in the rotated target frame, the corrected hit and true miss, all illumination angles and both subpoint results. Unloading the ephemeris produced the original scientific error and cleared failed state.
