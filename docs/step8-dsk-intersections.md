# DSK ray intersections and tolerances

E19 uses [E18’s checked DLA descriptor and segment storage](https://github.com/rybosome/tspice/pull/754). All five methods belong to the raw DSK API.

| Raw method                                                              | Scientific behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dskx02(handle, dladsc, vertex, raydir)`                                | Uses a live, owned DAS-backed handle and a descriptor obtained by DLA traversal. The nearest hit gives a one-based plate ID and a point in segment-frame km. An outgoing ray can miss; a zero direction signals RAYISZEROVECTOR. [NAIF](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dskx02_c.html)                                                                                                                                                                  |
| `dskxsi(pri, target, srflst, et, fixref, vertex, raydir, maxd?, maxi?)` | Searches loaded surfaces at ET seconds past J2000. A hit gives the target-frame point, borrowed KEEPER DAS number, all eight DLA fields, all 24 DSK fields and the type 2 source components. Those components are `dc=[]` and `ic=[plate ID]`. Both capacities default to one. [NAIF](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dskxsi_c.html)                                                                                                                    |
| `dskxv(pri, target, srflst, et, fixref, vertices, dirs)`                | Returns one found result per paired vertex and direction in input order. Misses omit coordinates. The two arrays must have equal lengths, and each row must contain three finite numbers. Zero rays reaches the real INVALIDCOUNT diagnostic. [NAIF](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dskxv_c.html)                                                                                                                                                      |
| `dskgtl(key)`, `dskstl(key, value)`                                     | Read or change runtime-wide DSK parameters. Keys 1–4 are mutable. Keys 5 and 6 signal IMMUTABLEVALUE on writes. Other keys signal INDEXOUTOFRANGE. The setter accepts finite signed values without further scientific validation. Save and explicitly restore old values; KEEPER kclear does not restore them. [DSKGTL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dskgtl_c.html) [DSKSTL](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/dskstl_c.html) |

## Results and lifetimes

Both loaded-kernel methods require `pri=false` in N0067. An empty surface list enables all matching surfaces. The nearest eligible hit can come from either file regardless of load order. A ray that misses eligible geometry returns `{found:false}`. With loaded geometry but no matching surface, the actual toolkit signals DSKDATANOTFOUND. Missing loaded DSKs, unknown target/frame IDs and frame center mismatch have separate diagnostics.

The source handle is the actual number observable in KEEPER’s `kdata` record. Read operations requiring a public `SpiceHandle` use a separate owned `dasopr` claim. The caller closes that claim; `unload` or `kclear` releases the loader’s reference. The source test unloads the winning file, observes the changed loaded-kernel intersection and reads the original plate from its still-open DAS claim. Every returned point, source array and descriptor is an independent copy.

## Pinned ABI

N0067’s `dskxsi_c` stores the DLA and DSK descriptors in private uninitialized arrays and unconditionally transfers them after the SPICELIB call. The transfer converts six descriptor doubles to integers even when the call has not defined any descriptor. Initializing a public caller’s structures cannot initialize these private arrays.

The shared shim uses the linked `dskxsi_` implementation and the declarations from the toolkit’s own `SpiceZfc.h`, preserving the outer `dskxsi_c` trace and CHKFSTR diagnostics. It initializes all caller storage and publishes the descriptors only on a confirmed hit. N0067 requires both source capacities to be at least one, uses one integer and no double values for the supported type 2 data, and passes neither capacity to its inner segment search. Positive caller capacities select actual buffers of the sufficient one-word size. Nonpositive counts reach the genuine toolkit error. The ledger records this single alias separately from the four direct matching C calls.

The independent Python sidecar binds the symbol in SpiceyPy 6.0.3’s own N0067 library with explicit argument types. On confirmed hits, it also calls the ordinary public SpiceyPy wrapper and checks every descriptor word, all point components, handle and plate against the separately obtained result. Misses and errors that reach the SPICELIB operation use the initialized callee only. For empty strings the C CHKFSTR entry returns before the private descriptor transfer, so the independent C-adapter call safely establishes the original EMPTYSTRING diagnostic. Zero-length ray arrays similarly use the real DSKXV C entry with a zero count and non-null sentinel storage. No fixture requires malformed DSK data.

## Independent geometry and coverage

The two synthetic octahedra have semiaxes (3,2,1) and (6,4,2) km. For vertex (10,1,0.25) and direction (−1,0,0), the analytic positive-face equation gives inner x = 0.75 km and outer x = 3.75 km. Both compiled backends returned those exact points, the independently expected facet normal, the segment’s actual one-based plate ID and the same source file as KEEPER. Cases exercise both load orders, the ET limits of the outer segment, a second rotated frame, selected surface lists, geometrical misses and mixed vector batches. Integer file numbers can differ between runtimes, so registered comparisons resolve each actual handle against its own KEEPER and compare the winning fixture filename. Dedicated public checks compare raw numbers directly within each runtime.

The 47 registered workflows contain 220 steps, 132 calls to the new methods and 26 terminal scientific errors. Both compiled backends passed 94 comparisons, ten public science/lifecycle checks, two native boundary tests and 26 WASM allocation-failure positions. Mutable tolerance tests capture each original value once and restore it after the case. Four of these checks use the public synchronous and asynchronous caches against both compiled backends. Repeating identical calls observes later tolerance writes, a newly selected surface following unload, and a closed DAS claim. All five operations bypass the default cache. The real Chrome worker exercised all five methods, both hits, source identity, complete descriptor fields, independent segment traversal, mixed rays, three errors and tolerance restoration.
