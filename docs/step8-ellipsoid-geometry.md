# Triaxial ellipsoid geometry

The seven raw methods operate on a centered ellipsoid with semiaxes `a`, `b` and `c` along the first, second and third coordinate axes. Lengths, point coordinates, altitude and distance use the caller’s common unit. Vector and ellipse fields are independent, owned arrays. These geometric operations read no kernels.

| Method                             | Geometric result                                                                                                                                                                                            |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nearpt(position,a,b,c)`           | A nearest boundary point and signed altitude, negative in the interior. For an interior point there can be more than one minimizer.                                                                         |
| `npedln(a,b,c,linept,linedr)`      | A nearest ellipsoid point and its nonnegative distance to the infinite line. For an intersection, CSPICE tries the input direction first and the opposite direction second.                                 |
| `edlimb(a,b,c,viewpt)`             | Apparent limb with an ellipsoid-centered origin for the input geometry. All three returned ellipse vectors have their usual origin and direction semantics. An exact surface view can yield zero limb axes. |
| `ednmpt(a,b,c,normal)`             | The surface point whose outward normal has the given direction.                                                                                                                                             |
| `edpnt(point,a,b,c)`               | Radial intersection along the ray from the origin through the nonzero input point. On a triaxial ellipsoid this can differ from the nearest boundary point.                                                 |
| `surfnm(a,b,c,point)`              | Outward unit normal for a surface point. At the origin the pinned calculation returns a zero vector.                                                                                                        |
| `surfpt(position,direction,a,b,c)` | Forward ray’s first intercept. A hit includes the point; an ordinary miss contains only `found: false`. An exactly recognized surface vertex is its own first intercept.                                    |

For axes `[3,2,1]`, the line through `[0,4,0]` parallel to the x-axis has nearest point `[0,2,0]` and distance 2. From `[5,0,0]`, the ray toward negative x first hits `[3,0,0]`; the ray toward positive x misses. The limb viewed from `[6,0,0]` has center `[1.5,0,0]` and axis lengths √3 and √3/2. The tests compare every component returned by the live oracle and independently measure the surface equation at sampled limb points, normal orthogonality to the sightline, and the point-to-line perpendicular distance. ## Numerical and error behavior

NEARPT checks the positive semiaxes, scaled axis ratios, and scaled coordinate products before its iteration. EDPNT reports `INVALIDRADII` for nonpositive radii and `POINTTOOSMALL` if the squared radial level of a nonzero point underflows. EDNMPT distinguishes `BADAXISLENGTH`, `AXISUNDERFLOW`, `ZEROVECTOR` and `DEGENERATECASE`. EDLIMB’s N0067 C implementation reports `DEGENERATECASE` for a nonpositive radius, interior viewpoint or a scaled axis square that vanishes. Exact tangency depends on the rounded geometric computation. [Point projection](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/edpnt_c.html) [Inverse normal map](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/ednmpt_c.html) [Nearest point](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/nearpt_c.html)

SURFPT’s public C wrapper unconditionally copies its private logical flag after calling the translated `surfpt_`. The latter assigns the flag after checking the zero direction and invalid axes. The shared shim invokes the exact external SPICELIB routine with initialized storage and preserves the `surfpt_c` outer trace. On error it retrieves the canonical short/long/trace fields before reading output. On a miss only the flag crosses the public boundary. For independent successes the sidecar compares the initialized typed ABI to ordinary locked SpiceyPy `surfpt`, including all three hit coordinates. Error probes use the initialized route alone. [Shared C implementation](../packages/backend-shim-c/src/domains/geometry.c) [Independent oracle](../packages/py-parity-checking/sidecars/spiceypy/src/py_parity_sidecar/ellipsoid_oracle.py)

EDLIMB and NPEDLN read private geometry or flags after some fallible nested operations. Both keep their directly linked public C routine. Before entry their adapters check the relevant canonical plane or nearest-point intermediates with initialized storage and the enclosing trace. The inherited INEDPL distorted-plane check preserves failure status for its caller. NPEDLN requires a representable projected nearest-point translation and scale. A finite direction with two largest-double components normalizes to zero in the pinned computation. Its nested ray then signals `ZEROVECTOR`; both compiled clients match the independent short, long and complete caller trace and recover for the following ray.
