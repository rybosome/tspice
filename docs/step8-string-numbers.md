# Numeric parsing and marker replacement

A21 extends the string domain introduced in A18. Its eleven methods each call the matching N0067 CSPICE routine on Node and WASM. No kernels are required. The contract specifies the output fields, signed caller capacities and strict UTF-8 boundary. [Public contract](../packages/backend-contract/src/domains/strings.ts) [Per-routine audit](../data/parity-audits/a21-string-numeric.json)

| Method | Exact observation                                                                                                                                                                                                                              |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| dp2hx  | Signed normalized hexadecimal encoding of a finite binary64 value. The returned `hxssiz` is the full payload length even when caller room truncates `hxstr`. A capacity below two signals a toolkit error.                                     |
| hx2dp  | A successful result contains the parsed number and empty message. A returned conversion error carries the exact message and omits the unspecified numeric output. Empty input and insufficient diagnostic room signal separate toolkit errors. |
| prsdp  | Decimal expressions accept embedded blanks, commas, D/E exponents, implicit mantissas and the PI mnemonic. Failed parsing signals NOTADPNUMBER.                                                                                                |
| prsint | Reuses the underlying decimal parse, truncates toward zero and checks the signed 32-bit result. Scientific parse or overflow failures signal NOTANINTEGER.                                                                                     |
| repmc  | Replaces the first matching marker, strips ASCII-space padding from the replacement and uses one interior blank for an empty replacement.                                                                                                      |
| repmct | Formats a signed integer as cardinal words in upper, lower or initial-capital case.                                                                                                                                                            |
| repmd  | Formats a finite double in toolkit scientific notation, clamping the significant-digit request into 1–14.                                                                                                                                      |
| repmf  | Formats a finite double in scientific or fixed notation. N0067 routes a non-E byte to its fixed formatter. Its fixed internal 56-byte string can truncate large or very small fixed-format values before the caller’s output capacity applies. |
| repmi  | Formats a signed decimal integer with full support for both 32-bit endpoints.                                                                                                                                                                  |
| repml  | Formats a boolean in one of three cases. A one-byte total capacity signals STRINGTOOSHORT even when the input is empty.                                                                                                                        |
| repmot | Produces ordinal words, preserving CSPICE hyphenation, sign and case selection.                                                                                                                                                                |

Marker matching and formatting use the toolkit’s byte semantics. The replacement methods process the first matching occurrence and trim trailing Fortran padding on the returned C string. For the six character, integer-word and numeric replacement wrappers other than REPML, a total capacity of one returns empty text. A byte-split result raises a representation error. Each default capacity covers the complete source plus its largest possible replacement and terminating NUL. The compiled adapters retain caller truncation, including capacities that signal a scientific error. Each allocation is bounded by signed 32-bit storage, and the WASM transport further limits each buffer to 256 MiB. ## N0067 arithmetic boundaries

The HX2DP exponent conversion and scaling are independent stages. Its translated integer helper uses signed left shifts in nibble accumulation, including when initializing its negative representable bound. This is a portability assumption of the pinned translated toolkit. The inspected Darwin arm64 binary emits ordinary word-width shift instructions. GCC documents its signed-shift extension; raw portability to arbitrary C compilers is outside the scope of these results. The actual N0067 native, separately built WASM and independent locked library agree on the ordinary signed exponents exercised here. The implementation calls the linked parser. [HX2DP](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/hx2dp_c.html) [GCC integer implementation](https://gcc.gnu.org/onlinedocs/gcc/Integers-implementation.html)

For a valid mantissa of at most 31 hexadecimal digits, the accumulated magnitude is zero or at least 16⁻³¹, and at most one after rounding. Scaling a nonzero mantissa by 16¹⁰²⁴ overflows binary64, while scaling any such mantissa by 16⁻¹⁰²⁴ underflows to zero. The shared shim therefore substitutes `400` or `-400` (hexadecimal 1024) only for a syntactically valid, representable signed exponent of greater magnitude. This avoids negation of the minimum signed integer and the inclusive maximum loop counter. It also bounds scientific work for long zero-mantissa scaling. The canonical parser produces the value or exact signed overflow diagnostic. Invalid integer exponents and malformed mantissas still reach the toolkit. Supplemental tests compare the guarded endpoints to the actual independently evaluated bounded inputs, never evaluating the dangerous original loop in the oracle. [Shared preflight](../packages/backend-shim-c/src/domains/strings.c) [Public endpoint checks](../packages/py-parity-checking/test/string-numbers.test.ts)

REPMCT and REPMOT call the private cardinal formatter INTTXT, which negates a negative signed argument. When the value is INT32_MIN, the shared shim rejects precisely the word conversion that would reach this arithmetic. Empty output, an absent marker and prior case validation preserve their usual behavior. REPMI formats the same minimum through INTSTR and returns its decimal spelling. [Cardinal conversion](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/repmct_c.html) [Ordinal conversion](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/repmot_c.html)

## Independent evidence

The 65 registered workflows contain 225 actual new calls and 23 genuine terminal scientific errors. Both compiled backends passed all 130 registered live comparisons. Seven supplemental public tests check exact binary64 round trips and signed zero normalization, the bounded exponent domain, UTF-8 representation, integer-word guards and recovery. Fifteen native boundary tests and 54 WASM tests exercise invalid arguments, caller capacities, strict result ownership and allocation failure/recovery. Real Chrome exercised all eleven methods, including hexadecimal round trips, returned error flags, marker forms, a genuine SPICE error and recovery. The sync and async public facades typecheck in the non-DOM consumer. [Public comparisons](../packages/py-parity-checking/test/string-numbers.test.ts) [Native boundaries](../packages/backend-node/test/string-numbers-domain.test.ts) [WASM storage](../packages/backend-wasm/test/string-numbers-allocations.test.ts)

The locked SpiceyPy 6.0.3 distribution supplies the independent N0067 binary. PRSDP and PRSINT use its checked Python wrappers. Explicit ctypes signatures preserve all DP2HX and HX2DP result fields, arbitrary diagnostic capacities, exact bytes and all seven replacement forms. The missing top-level REPML wrapper is bound directly to that library’s exported canonical symbol. Common ASCII cases cross-check the exposed high-level wrappers. A sentinel verifies HX2DP leaves the numeric output untouched on scientific conversion errors. Numeric fixtures consist of authored strings, dyadic values, binary64 limits and integer boundaries.
